为什么学这个

前面七章我们一直在用一种「老方法」写程序

回想一下：从第一章到第七章，我们写的所有程序——先输入、再判断、再循环、最后输出——都是把任务拆成一步一步的函数依次执行。这种方式叫面向过程编程。它很直观，小问题随手就能写；但当程序变大、数据越来越多时，「一堆函数 + 一堆散装变量」就会越来越难管理。

本章要学的面向对象编程是另一种组织代码的思路：先把「数据」和「操作数据的函数」打包成一个对象，再让对象之间协作完成任务。它是现代软件的主流写法，也是读懂别人代码、继续深入 Python 的必修课。本章是扩展章，重在理解思路，跟着「试一试」练手即可。

💡 打个比方
同一道番茄炒蛋，两种做饭哲学

面向过程像照着菜谱自己掌勺：洗番茄 → 打鸡蛋 → 热锅倒油 → 炒蛋盛出 → 炒番茄 → 混合调味 → 装盘——一步接一步，步骤清晰，全程靠你自己执行。

面向对象像当一回「指挥家」：厨师对象有会炒菜的方法，番茄、鸡蛋是食材对象各有自己的属性（新鲜度、数量），锅和铲子是厨具对象负责受热和翻炒——你只需要让这些对象各司其职、相互配合，菜就做出来了。

核心概念

两种范式到底差在哪

  • 面向过程编程（POP，Procedure Oriented Programming）：以解决问题的步骤为核心，将程序分解为一组有序的函数（或过程）依次执行
  • 面向对象编程（OOP，Object Oriented Programming）：以现实世界中的对象为核心，将数据和操作封装在一起，通过对象之间的交互完成任务
  • 没有优劣之分：简单脚本用面向过程更快，大型系统用面向对象更好维护——工程师根据场景选择
  • 面向对象不是抛弃函数：方法本质还是函数，只是被装进了对象里
对比维度面向过程 POP面向对象 OOP
核心解决问题的步骤现实世界中的对象
组织方式函数按顺序依次执行数据 + 操作封装进对象，对象协作
思维习惯「怎么做」——一步步来「谁来做」——找对对象

交互示例

同一件事：「判断成绩并输出结果」的两种写法

点下面的按钮切换对比——任务完全相同，组织代码的方式完全不同。

# 面向过程：把任务拆成一步接一步的函数
def input_score():                     # 第 1 步：输入
    return int(input('请输入成绩：'))

def check(score):                      # 第 2 步：判断
    return score >= 60

def show(score, ok):                   # 第 3 步：输出
    if ok:
        print(f'{score}分，及格！')
    else:
        print(f'{score}分，不及格。')

score = input_score()    # 主线：函数按顺序排队执行
result = check(score)
show(score, result)
  • 数据和函数是分开的：score 是散装变量，check、show 是散装函数
  • 执行主线清清楚楚：第 1 步输入 → 第 2 步判断 → 第 3 步输出
# 面向对象：把数据和操作装进一个「学生」对象
class Student:
    def __init__(self, name, score):   # 初始化：把数据装进对象
        self.name = name
        self.score = score

    def show(self):                    # 判断 + 输出都是对象自己的行为
        if self.score >= 60:
            print(f'{self.name}：{self.score}分，及格！')
        else:
            print(f'{self.name}：{self.score}分，不及格。')

s = Student('小明', 87)   # 造一个学生对象（下一节起细讲）
s.show()                  # 让对象自己干活，主程序只剩两行
  • 数据（name、score）和操作（show）被封装在同一个类里
  • 主程序不再「一步步指挥」，而是「找对对象、让它干活」——s.show() 一行搞定

面向过程编程（POP）以解决问题的＿＿为核心；面向对象编程（OOP）以现实世界中的＿＿为核心。（两空用空格隔开）

⚠️ 避坑
三个初学误区

①以为面向对象「更高级」就全盘取代面向过程：写个小脚本算个平均分，面向过程三行搞定，硬套类反而累赘——工具要看场合；

②以为学了面向对象函数就没用了：方法（method）本质就是定义在类里的函数，前七章的函数功底恰恰是本章的地基；

③把「范式」和「语法」混为一谈：范式是组织代码的思路，不是新语法——本章学的 class 只是把这个思路落地的工具。

✅ 小结
你现在知道了

面向过程以步骤为核心，程序是一组有序函数依次执行；面向对象以对象为核心，数据和操作封装在一起、对象协作完成任务。两种范式没有优劣——前七章是面向过程，本章开始学面向对象。下一节：先认识面向对象的三大特性。
