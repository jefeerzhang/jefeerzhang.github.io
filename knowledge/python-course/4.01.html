为什么学这个

列表太自由了，有些数据我想「锁起来」

第三章你学会了列表——想加就加、想删就删、随时能改。但现实中很多数据恰恰不希望被改动：一组固定配置、一个坐标点、一年 12 个月的名称……如果代码里某处不小心把它们改了，bug 会藏得很深很难查。Python 为这种「只读数据」准备了专门的类型：元组（tuple）。

元组是由 0 个或多个元素组成的有序序列，在 Python 中属于有序且不可变的序列数据类型，使用小括号 () 包裹元素。它兼具列表的序列特性与常量的稳定性，适合存储固定配置或异构数据集合。本章作业第 1 题（用元组存坐标）就是它的直接应用。

💡 打个比方
从白板到塑封卡片

延续第三章的比喻：字符串是「刻在石碑上的字」，列表是「白板上的购物清单」——想擦就擦、想加就加；而元组是「塑封好的卡片」——卡片上的内容看得见、传得动，但塑封之后谁也涂改不了。需要展示和传递固定信息时，塑封卡片远比白板可靠。这个「塑封」的比喻会贯穿整个元组部分，请记住它。

核心概念

三大特性：有序、不可变、任意类型

  • 有序性：元素按插入顺序排列，支持通过索引（Index）直接访问——和字符串、列表的规则一样
  • 不可变性：一旦创建，无法修改、添加或删除元素，数据安全性高——这是元组与列表最本质的区别
  • 任意类型：元素可以包含数字、字符串、列表，甚至其他元组等不同类型，想混装就混装
  • 一句话记住：元组 = 有序 + 只读 + 什么都能装

不可变性

tp = (1, 2, 3) 之后执行 tp[0] = 99，会直接报 TypeError。想「改」元组，只能创建一个新的元组来代替。

❓ 测验

下列哪种说法是错误的？

✏️ 填空

元组一旦创建，无法____、____或____元素。（三空连填，用空格隔开）

⚠️ 避坑
括号不是身份证，逗号才是

新手常以为「加了小括号就是元组」——错！type((5)) 的结果是 <class 'int'>，因为 (5) 只是带括号的数字 5；type((5,)) 才是 <class 'tuple'>。真正标志元组身份的是逗号，这个本章第一大坑下一节专门讲透。

另一个坑：「不可变」不等于「元素内部完全不可改」——如果元素本身是个列表，比如 (1, [2, 3])，那个列表内部仍然可以修改。这个问题 4.06 会用 id 帮你彻底搞懂。

🔧 试一试：验证混装与类型（5 分钟）
  1. 打开 IDLE 的交互模式（Shell），输入 (1, 'a', [2, 3], (4, 5)) 并回车——整数、字符串、列表、元组混装，完全合法。
  2. 输入 x = (1, 'a', [2, 3], (4, 5))，再输入 type(x)——看到 <class 'tuple'>，确认它就是元组。
  3. 输入 len(x)——结果是 4：不管元素是什么类型，元组只按「个数」计数。
  4. 试着输入 x[0] = 99——亲眼看看不可变性的报错长什么样（学完下一节索引后你会更明白）。
✅ 小结
你现在知道了

元组是由 0 个或多个元素组成的有序序列，是 Python 中有序且不可变的序列数据类型，用小括号 () 包裹。三大特性：有序性（索引访问）、不可变性（不能改、加、删元素）、任意类型（元素可混装嵌套）。它适合存固定配置和受保护数据。下一节：元组的各种创建姿势——单元素元组有个天大的坑。
