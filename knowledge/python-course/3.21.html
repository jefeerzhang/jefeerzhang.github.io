为什么学这个

把 20 节所学，拧成一段真程序

这是本章最后一节：老师拿到全班 10 个成绩，要出一份「成绩报告单」——报最高分、最低分、平均分，按名次排队，再查某人排第几、有几个同分。这些一步不多、一步不少地用到了前面学的 max / min / sum / len、sort、index、count、f-string。看懂它，本章就毕业了；本章作业第 1 题也是它的简化版。

💡 打个比方
老师出成绩单的完整流程

第一步「报数据」：翻一眼成绩册，报出最高、最低和平均分（统计三板斧）；第二步「排队」：让全班按分数从高到低站好（sort 降序）；第三步「点名」：队站好后，88 分的同学站在第 5 个位置——位置即名次，再数一数有几个同分的。整段程序就是这三个动作的代码化。

核心概念

完整代码：成绩单生成器

scores = [85, 92, 70, 90, 88, 75, 95, 82, 89, 70]

# ① 统计三板斧
print(f"最高分：{max(scores)} 分")
print(f"最低分：{min(scores)} 分")
print(f"平均分：{sum(scores) / len(scores)} 分")

# ② 就地降序排序
scores.sort(reverse=True)
print(f"成绩降序：{scores}")

# ③ 排名与同分查询
score = 88
print(f"{score}分排第{scores.index(score)+1}")
print(f"{score}分有{scores.count(score)}人")

输出结果：

最高分：95 分
最低分：70 分
平均分：83.6 分
成绩降序：[95, 92, 90, 89, 88, 85, 82, 75, 70, 70]
88分排第5
88分有1人
逐段拆解
  • 统计三板斧：max / min 直接取极值；平均分 = sum(scores) / len(scores)——总和除以人数，得 83.6
  • sort(reverse=True)：就地降序，原列表 scores 已经被改变——此后 scores 都是从大到小排好的
  • index + 1 = 名次：降序排列后位置即排名，index(88) 得下标 4，+1 才是人类习惯的「第 5 名」（下标从 0 起）
  • count 统计同分人数：88 分有 1 人；若 70 分就是 count(70) → 2 人

🔬 两个视角看这段代码

max(scores)　→　95　（最高的那颗豆子）
min(scores)　→　70　（最低的那颗）
sum(scores)/len(scores)　→　83.6　（总重÷人数）
# 三行只「看」不「改」，原列表安然无恙
scores.sort(reverse=True)　# 就地降序，原列表已变！
scores.index(88)　→　4　（0 起的下标）
scores.index(88) + 1　→　5　（第 5 名）
# 排完队，位置就是名次，只是别忘了 +1
课堂代码

两个易被追问的细节

scores = [70, 90, 88]
print(sum(scores) / len(scores))   # 82.66666666666667　除法结果不四舍五入
scores.sort(reverse=True)
print(scores.index(88))            # 1　降序后 [90, 88, 70]，88 在下标 1，名次 2
  • 平均分可能除出长小数，课堂例题里 83.6 只是恰好整；想美化可配合 format / f-string 的精度控制
  • index 必须在排序之后调用才是名次——排序前 index(88) 只是在原列表里找位置，与名次无关
❓ 测验

执行 scores.sort(reverse=True) 之后，scores.index(88)+1 表示什么？

✏️ 填空

平均分 = sum(scores) / ＿＿。

⚠️ 避坑
排序会「毁尸灭迹」：原顺序回不来了

sort 是就地修改：执行 scores.sort(reverse=True) 后，原来的成绩录入顺序永久丢失。如果之后还需要按学号顺序打印成绩单，应先用 scores2 = scores.copy() 备份一份再排。

名次 +1 别忘写：index 返回的是 0 起的下标，忘写 +1，报告单上「88分排第4」就闹笑话了。另外 index 找不到该分数会直接报 ValueError——查询前最好先用 in 判断这个分数存不存在。
