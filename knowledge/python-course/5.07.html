为什么学这个

同一件事两种写法——凭什么多分支更受推荐？

上一节说「嵌套不宜超过 2 层，建议转成多分支」，但光说不练不算懂。这一节把 PPT 里的经典例题——酒驾判定——的两种写法摆在一起：先看国家标准的三个档位，再看嵌套版和多分支版怎么各自实现它，你会发现两段代码完全等价，但读起来的轻松程度差很多。

< 20
不构成酒驾
≥ 20 且 < 80
饮酒驾车
≥ 80
醉酒驾车

依据：国家《车辆驾驶人员血液、呼气酒精含量阈值与检验》——血液酒精含量小于 20mg/100ml 不构成饮酒驾驶；大于等于 20mg/100ml、小于 80mg/100ml 为饮酒驾车；大于等于 80mg/100ml 为醉酒驾车。

💡 打个比方
嵌套版像「进了大门再分小门」，多分支版像「大门口直接挂三块指示牌」

嵌套版要先推开大门（外层 if），进去之后才看到小门上的分流指示；多分支版则是站在大门口就把三块牌子看完——第一块不符看第二块，第二块不符看第三块，一进一出直达目的地。目的地一样，但后者少绕一层：不用记「我现在站在大门里还是大门外」，眼睛从上到下扫一遍就够了。

交互示例

酒驾判定：嵌套版 vs 多分支版（完全等价）

res = eval(input('请输入每百毫升血液酒精含量！'))
if res < 20:
    print('不构成酒驾，可以开车')
else:
    if res < 80:
        print('达到酒驾标准，不能开车！')
    else:
        print('达到醉酒标准，千万不能开车！')
  • 外层 res < 20：真 → 不构成酒驾；假 → 才进 else 里的小门
  • 内层 res < 80：真 → 酒驾标准；假 → 醉酒标准
🔍 读嵌套要把隐含条件补全：内层的 res < 80 能被判断到，说明外层 res < 20 已经为假，即隐含 res ≥ 20。所以它的真实含义是「20 ≤ res < 80」——不补全这一步，很容易读错。
res = eval(input('请输入每百毫升血液酒精含量！'))
if res < 20:
    print('不构成酒驾，可以开车')
elif res < 80:
    print('达到酒驾标准，不能开车！')
else:
    print('达到醉酒标准，千万不能开车！')
  • 三个档位平铺在同一层，从上到下命中即停，没有里外两层的嵌套关系
  • elif res < 80 同样隐含 res ≥ 20（能走到这行说明上面为假）——但「命中即停」的规则大家都熟，读起来更不容易绕
  • 两段代码对任何输入的输出一模一样——这就叫「等价」

❓ 测验

运行上面的判定程序，输入 80 时输出什么？

✏️ 填空

依据国家《车辆驾驶人员血液、呼气酒精含量阈值与检验》：血液酒精含量大于或等于 20mg/100ml、小于 80mg/100ml 为＿＿驾车。

⚠️ 避坑
读嵌套代码的头号陷阱：隐含条件

嵌套版里内层的 res < 80 隐含了「res ≥ 20」这个前提——因为能走到 else 里，说明外层 res < 20 已经不成立。读嵌套代码要把隐含条件补全才不出错：内层条件的真实含义永远是「前面全部为假 且 本条件为真」。养成「逐层补前置条件」的习惯，读任何嵌套代码都不会晕；反过来写代码时，能写成多分支的平铺条件，就别套两层门。

✅ 小结
你现在知道了

同一逻辑，嵌套和多分支写出来完全等价：嵌套版「进了大门再分小门」，多分支版「大门口直接挂三块指示牌」。多分支平铺、易读，是 PPT 推荐的写法——嵌套不宜超过 2 层，能转多分支就转。读嵌套代码时记得补全隐含条件（内层条件 = 前面全假 且 本条件为真）。下一节：进入循环的世界——循环次数不确定的无限循环 while。
