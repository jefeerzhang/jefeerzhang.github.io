为什么学这个

Python 的「卷面分」是硬指标

别的语言用花括号 { } 划分代码块，Python 却靠缩进——缩进不是「好看」，而是语法的一部分，错一个空格程序就跑不起来。而注释则是写给「三个月后的自己」的备忘录。这一节两件事：

  • 缩进规则：同一代码块为什么必须对齐？错在哪会报什么错？
  • 注释规范：单行注释、行尾注释、多行注释分别怎么写？
💡 打个比方
缩进像作文段落空两格，注释像快递单备注

写作文时，同一段落必须整齐对齐——段落开头空两格、每行左对齐，错乱了老师会直接退回。Python 解释器就是那位严格的老师：缩进错乱？直接报错退稿。而注释像快递单上的备注：「易碎，轻拿轻放」——是写给以后的自己和他人看的说明，程序运行时会完全无视它。

核心概念

缩进规则与注释规范

  • 缩进核心规则：同一代码块必须保持相同缩进量，用于区分语句层级。
  • 规范建议：按 PEP 8，推荐用 4 个空格作为一个缩进层级（在 IDLE 里按 Tab 键会自动补成 4 个空格）。
  • 应用场景：if、while、for、def、class 等关键字后的子句块——它们的标志是冒号(:)，冒号下面就是缩进的代码块。
  • 错误提示：出现 unexpected indent 错误，说明存在语句缩进问题。
  • 单行注释：以 # 开头，可位于行首（行注释），也可放在代码结尾（行尾注释）。
  • 多行注释：用三个单引号或双引号包裹（俗称「三引号字符串」——Python 并没有专门的多行注释语法，是借它当注释用），通常用于对整个函数或模块进行说明。
  • 最佳实践：注释应解释为什么这么做，而非做了什么。
  • 快捷方式：添加注释可使用快捷键 CTRL+/。
实战演示

缩进对与错，一眼定输赢

if 1 > 0:
    print('条件成立')    # 同一代码块，缩进一致
    print('执行完毕')    # 缩进量与上一行相同

两条 print 都属于 if 的子句块，缩进量完全相同——运行正常，两行都输出。

if 1 > 0:
    print('条件成立')
  print('执行完毕')       # ← IndentationError！这行缩进量比上一行少

这行比上一行少缩进 2 格，又对不上外层的任何一级缩进，解释器当场报错：IndentationError: unindent does not match any outer indentation level——意思是「减少缩进后，和外面任何一级缩进都对不上」。

再来看注释三兄弟的完整演示（课程例题）：

# 这是行注释：单独占一行，解释下面的代码
print(123)  # 这是行尾注释：跟在代码后面

def fun1(a):
    '''这是多行注释：用三引号包裹，
    通常用于说明整个函数的功能'''
    pass  # 函数实现没想好，用 pass 占位

print(fun1.__doc__)  # 输出函数说明

输出结果：123 与 这是多行注释：用三引号包裹，
通常用于说明整个函数的功能

💡 说明：注释本身不参与运行，所以第一个输出是 123；fun1.__doc__ 会取出函数体开头那段三引号注释（学名「文档字符串」），这就是多行注释的妙用。注意 Python 3.13 起编译器会自动剥掉 docstring 每行共有的前导空白，所以第二行那 4 个缩进空格不会出现在 __doc__ 里。函数还没想好怎么写时，用 pass 占位防止报错。

❓ 测验

程序运行出现 unexpected indent 错误，说明了什么？

✏️ 填空

单行注释以＿＿开头；添加注释的快捷键是＿＿。（两空连填，中间用空格隔开，如：@ CTRL+X 的格式）

⚠️ 避坑
空格和 Tab 混用，是缩进错误的高发区

规范建议每个缩进层级用 4 个空格，不要手动敲一长串空格，更不要混用 Tab。最隐蔽的坑是空格与 Tab 混用：屏幕上看两行「对齐了」，但空格算 1 个字符、Tab 算 1 个缩进单位，解释器眼里它们并不相等，照样报 TabError: inconsistent use of tabs and spaces in indentation（TabError 是 IndentationError 的子类）。所以：同一份代码里只能用一种，别混用。

另一个提醒：三引号要成对出现——开了 ''' 就必须用 ''' 收尾，混用不同引号会让字符串一直「吃」到很远的地方，报一堆莫名其妙的错。

🔧 试一试：故意制造一个缩进错误（3 分钟）
  1. 打开命令行输入 python 进入交互模式。
  2. 输入 if 1>0: 回车——注意行尾的冒号，它宣告「下面是一个缩进块」。
  3. 下一行先正常输入 print('ok') 回车，应该输出 ok。
  4. 再来一次：输入 if 1>0: 回车后，先敲 4 个空格输入 print('a')，再只敲 2 个空格输入 print('b')——把缩进「倒回去」，但没回到最外层。
  5. 观察报错信息：IndentationError: unindent does not match any outer indentation level（箭头指向 print('b') 那一行）——恭喜，你亲手复现了本节最重要的错误。注意：如果只是在缩进块里「多敲几个空格」，Python 反而不报错，只要这一块内部保持一致即可。
  6. 再试试把 # 这是注释 敲进去，观察解释器如何「无视」它。
✅ 小结
你现在知道了

缩进是 Python 的语法：同一代码块必须缩进一致，冒号(:)后跟缩进块，Tab 键缩进更规范，缩进出错会报 IndentationError（如 unexpected indent、unindent does not match any outer indentation level）。注释有三种：# 行注释、行尾注释、三引号多行注释（可用 __doc__ 取出），快捷键 CTRL+/，最佳实践是写「为什么」而不是「做了什么」。下一节：正式进入数值世界——数值类型总览。
