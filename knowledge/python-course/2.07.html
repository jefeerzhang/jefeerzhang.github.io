为什么学这个

写过的代码，别再抄第二遍

想象你写了一段「计算成绩平均分」的代码，程序里有 5 个地方都要用。难道复制粘贴 5 遍？以后改一个字符就要改 5 处。函数就是解决这个问题的利器。这一节你将收获：

  • 模块化设计：把复杂问题拆解成一个个小模块，逻辑更清晰
  • 代码复用：一次定义，多次调用，避免重复造轮子
  • 高可读性：给函数起个语义化的名字，别人一眼就看懂这段代码干什么
💡 打个比方
函数 = 自动售货机

你投币（输入参数）→ 机器在内部哗啦运作（函数体）→ 掉出一瓶饮料（返回结果）。你完全不需要懂售货机内部构造，会用就行。函数也是一样：调用者只管「给什么、得什么」，内部逻辑封装在里面。

核心概念

什么是函数？

  • 定义：函数是组织好的、可重复使用的代码段，用于实现单一或相关联的功能。
  • 数学类比 y = f(x)：x（输入）= 函数的参数；f（处理）= 函数体（代码逻辑）；y（输出）= 函数的返回结果。
  • 函数定义：指创建一个函数，供自己或他人使用——相当于「造好这台售货机」。
  • 函数调用：指将具体数据带入函数中得到处理结果的过程。调用时，计算机将自动完成函数执行和函数结果返回——相当于「投币取饮料」。

工位① 输入参数 x

函数的「原料入口」
调用函数时把具体数据交给它，比如 abs(-5) 中的 -5。原料不同，产出的结果也不同。

工位② 函数处理 f

函数体里的「加工车间」
一段封装好的代码逻辑，对参数进行计算处理。写一次，之后每次调用都自动执行，这就是「一次定义，多次调用」。

函数的「成品出口」
处理完成后返回结果给调用处。比如 abs(-5) 的返回结果是 5，可以存进变量、继续参与运算。

实战演示

定义视角 vs 调用视角

def greet(name):
    print('你好，' + name + '！')
    return 'done'

用 def 函数名(参数): 创建函数，缩进的函数体是「加工逻辑」。此时它只是被定义，还不会执行——机器造好了，但没人投币就不出货。

greet('小明')      # 输出：你好，小明！
greet('小红')      # 输出：你好，小红！

用「函数名(具体数据)」调用，计算机自动完成函数执行和结果返回。注意调用前必须先运行左边的 def greet(name):，否则会报 NameError: name 'greet' is not defined。同一个函数，换不同参数反复调用——代码复用达成。

❓ 测验

「将具体数据带入到函数中得到处理结果的过程」叫什么？

✏️ 填空

数学类比 y = f(x) 中：x 是函数的＿＿，y 是函数的＿＿。（两空连填，中间用空格隔开）

⚠️ 避坑
只定义不调用，函数等于白写

def 只是「造好了机器」，不调用就不会执行。很多初学者定义完函数，发现函数体里的 print 什么都没输出，一脸疑惑——因为没人「投币」，机器不会自己动。记住：定义 ≠ 执行，必须写出 函数名(参数) 这一步。

另一个小坑：调用时参数个数要和定义匹配，机器是按「投币口」设计来收原料的，乱塞会报错。

🔧 试一试：体验一次「投币取货」（3 分钟）
  1. 打开命令行输入 python 进入交互模式（第一章学过）。
  2. 输入 abs(-5) 回车——abs 是 Python 自带的函数，这里你扮演的是调用者。
  3. 想一想流水线三工位：输入是什么？（-5）处理是什么？（求绝对值的逻辑）输出是什么？（5）。
  4. 再换个参数调用：abs(3)、abs(-100)——同一台「机器」，不同的「原料」，产出不同结果，这就是一次定义、多次调用。
✅ 小结
你现在知道了

函数是组织好的、可重复使用的代码段，带来模块化、代码复用、高可读性三大好处。y = f(x) 里：x 是参数、f 是函数体、y 是返回结果。定义是创建函数，调用是把具体数据带进去得到结果。下一节：Python 自带了哪些开箱即用的函数？
