为什么学这个

「不可变」到底锁住了什么？

前面五节一直说元组不可变，但如果元组里装了一个列表呢？列表自己可是能改的！这节用一个坐标 location = (30.57, [104.07]) 做三步实验，把「不可变」的真正含义——元组中存放的引用不可变——彻底讲透。想明白这一点，你就懂了为什么本章作业第 1 题要用元组存坐标：安全、防误改。

💡 打个比方
上锁的文件柜与抽屉里的书包

元组像上锁的文件柜：柜子里每个抽屉的位置永远不变（引用固定），1 号抽屉永远是 1 号抽屉。但如果 1 号抽屉里放的是个书包（列表），书包里面的东西还是可以随便换——柜子锁的是「抽屉安排」，不是「抽屉里物品的内部」。所以 location[1][0]=140.07 能成功（换书包里的东西），而 location[1]=140.07 会失败（想把 1 号抽屉整个换成别的东西——柜子不让）。

核心概念

不可变 ≠ 万物皆不可改

  • 准确含义：元组的不可变，指的是元组中存放的引用不可变——location[1] 永远指向原来那个列表对象
  • 元素是可变对象时，对象内部可以修改：location[1][0] = 140.07 完全合法
  • 给元组元素赋值会报错：location[1] = 140.07 报 TypeError——这不是换内容，而是想换引用，被锁死了
  • 整体重新赋值是另一回事：location = (30.57, [140.07]) 合法，但这是创建了一个新元组、让变量换个指向，不是修改原元组
  • id() 能查看对象的内存地址：地址不变说明还是同一个对象，地址变了就是新对象
交互示例

🔬 三步实验：锁柜子的边界在哪里

location = (30.57, [104.07])——元组里装了一个列表

location[1] = 140.07

输出：

TypeError: 'tuple' object does not support item assignment

解读：想把 1 号「抽屉」整个换掉——柜子上着锁，Python 直接拒绝。

location[1][0] = 140.07
print(location)
print(id(location), id(location[1]))

输出：

(30.57, [140.07])
1516683075264 1516683642624

解读：只换书包里的东西、不动抽屉——修改成功！元组和列表的 id 都没变，说明还是原来那两个对象，变的只是列表内部的内容。

location = (30.57, [140.07])
print(id(location), id(location[1]))

输出：

1516683103872 1516683643200

解读：这是新建了一个元组再让 location 指过去——不是修改。对比第二步的 id，两个地址全变了。

课堂代码

PPT 原例：完整跑一遍，盯住 id 的变化

location = (30.57, [104.07])
print(f"经度：{location[0]}，纬度：{location[1]}")
# location[1] = 140.07      # 想换掉元素，报 TypeError，因此注释掉
print(id(location), id(location[1]))
location[1][0] = 140.07     # 修改列表内部，合法
print(f"经度：{location[0]}，纬度：{location[1]}")
print(id(location), id(location[1]))
location = (30.57, [140.07])    # 整体重新赋值：创建新元组
print(id(location), id(location[1]))

输出结果：

经度：30.57，纬度：[104.07]
1516683075264 1516683642624
经度：30.57，纬度：[140.07]
1516683075264 1516683642624
1516683103872 1516683643200
  • 第二次 print id：修改列表内部后，两个 id 完全没变——元组还是那个元组、列表还是那个列表，变的只是列表的内容
  • 第三次 print id：整体重新赋值后两个 id 全变——新元组、新列表，变量换了指向
  • 三组 id 一对比，「不可变」指的就是：元组存放的引用不换
❓ 测验

location = (30.57, [104.07])，执行 location[1][0] = 140.07 会？

✏️ 填空

元组的不可变性指的是元组中存放的____不可变，而非元素内部完全不可改。

⚠️ 避坑
关于「不可变」的三个误区

误区一：以为「元组不可变 = 装什么都绝对改不了」。遇到列表元素，内部照样能改。想要真·只读，元素应全用不可变类型（数字、字符串、元组）。

误区二：以为 location = (30.57, [140.07]) 是「修改了元组」——其实是创建了新元组让变量重新指向，id 全变。修改和重新赋值是两回事。

误区三：id 的数值每次运行、每台电脑都不同——你跑出来的地址和课件不一样是正常的，重点看「同一次运行里变没变」。

✅ 小结
你现在知道了

「不可变」指的是元组中存放的引用不可变：location[1] 永远指向原来那个列表；列表内部可以改（location[1][0]=140.07 成功且 id 不变），给元素赋值不行（location[1]=140.07 报 TypeError）；整体重新赋值是创建新元组、id 全变。元组适合存坐标这类受保护数据——这正是作业第 1 题的用意。下一节进入第二部分：集合。
