为什么学这个

同一句 speak()，为什么狗叫汪汪、猫叫喵喵？

继承让子类「全盘接收」父类的方法，但接收来的方法未必合身——Animal 的 speak() 对 Dog 和 Cat 来说都该「开口」，可开口的声音理应不同。多态指同一个方法在不同子类对象上调用时，会根据对象所属子类的不同产生不同的行为。实现它的手段是方法重写：子类中定义与父类同名的方法，覆盖父类的实现。这是面向对象三大特性的最后一块拼图。

💡 打个比方
多态像「舞台上的指挥家」：统一手势，各自发声

指挥家做出统一的「演奏」手势（统一的接口），面前的小提琴、鼓、长笛接收到同一个指令后，根据自身特性发出完全不同的声音。代码里也是如此：我们只管对每个对象调用 speak()，至于是「汪汪汪」还是「喵喵喵」，由对象自己的类说了算——调用方不用写一堆 if 去分辨对象类型，这就是多态的省心之处。

核心概念

实现多态：继承打底，重写发声

  • 继承 + 方法重写：多态通过继承和方法重写实现——先有父子关系，子类再覆盖同名方法
  • 方法重写（Override）：子类中定义与父类同名的方法，覆盖父类的实现；调用时执行子类自己的版本
  • 方法名必须完全一致：重写要求方法名称完全一致；参数的数量和位置不强制，保持一致才符合「同一个接口、不同实现」的多态本意
  • 不强制类型检查：Python 不检查对象的类型，只要对象有这个方法就能调用，从而轻松实现多态
  • 与 super() 的分工（对照 8.09）：重写是「覆盖换新」——子类完全用自己的版本；super() 是「先借父类的再用」——在父类实现的基础上补充

🔬 多态实验台：点按钮执行 PPT 测试流程（Dog、Cat 都重写了 speak）

点按钮模拟运行～同一句 speak()，不同对象不同声音。
课堂代码

PPT 原例：Animal 家族的重写

class Animal:                       # 父类：只定接口
    def speak(self):
        pass

class Dog(Animal):
    def speak(self):                # 重写父类方法
        print('汪汪汪！')

class Cat(Animal):
    def speak(self):                # 重写父类方法
        print('喵喵喵~')

Dog().speak()
Cat().speak()

输出结果：

汪汪汪！
喵喵喵~
  • 两个子类都定义了与父类同名的 speak——各自的版本覆盖了父类的 pass
  • 调用 Dog().speak() 和 Cat().speak() 写法完全一样，行为却不同——这就是多态
  • 就算写成 for a in [Dog(), Cat()]: a.speak()，循环也无需判断类型：每个对象自动调用自己的 speak

✏️ 填空

方法重写的规矩：子类中定义与父类＿＿完全相同的方法，覆盖父类的实现；同时要求参数的数量和＿＿尽量保持一致。（两空用空格隔开）

⚠️ 避坑
三个高频翻车点

①方法名拼错就不算重写：写成 Speak（大写 S）或 speak2，Python 不会报错，只会当成新增方法——调用时执行的仍是父类的 pass，一声不吭；

②重写 __init__ 别忘 super()：多态常伴着重写，但重写 __init__ 时要回到 8.09 的铁律——先 super().__init__()，否则父类属性没初始化；

③「有该方法」是前提：Python 不检查类型，但对象没有这个方法时照样 AttributeError——比如让一个既没继承 Animal、自己也没写 speak() 的对象去调用 speak() 就会翻车；只要它继承了 Animal，父类的 speak() 照样能调。

✅ 小结
你现在知道了

多态指同一个方法在不同子类对象上调用时，会根据对象所属子类的不同产生不同的行为；它通过继承 + 方法重写实现：子类定义与父类同名的方法覆盖父类实现，方法名必须完全一致，参数的数量和位置最好也保持一致；Python 不强制类型检查，只要对象有该方法就能调用，轻松实现多态。对照 8.09 记一句：重写是「覆盖换新」，super() 是「先借父类的再用」。下一节综合案例把本章所有知识合体——收尾之战！
