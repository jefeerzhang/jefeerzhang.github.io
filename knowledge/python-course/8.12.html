为什么学这个

把本章学的一切，装进一个能跑的「小商店」

前面十一节你已经集齐了面向对象的全部零件：类与对象、实例属性与类属性、三种方法、私有属性、继承与重写。现在到了「合体」时刻——这个商品库存管理案例把所有知识点用在同一个类里：公开名字、私有价格和库存、私有方法算折后价、实例方法卖货、类方法全场打折。看懂它，这一章就真正通了。

💡 打个比方
Product 类像一家「连锁便利店」的运营手册

每个商品对象是一家分店：店名（name）挂在大门口人人可见——公开属性；现金和库存锁在后仓——私有属性；后仓的内部核价流程员工才懂——私有方法；收银台对顾客开放——公开方法；而「全场八折」是总部一条通知，所有分店同步生效——类属性 + 类方法。一家手册，千店运转，这正是封装与复用的味道。

核心概念

Product 类的设计思路

  • 类属性：discount = 1.0——全场折扣，所有商品共享一个值，改一处全体生效
  • 实例属性：self.name 公开；self.__price、self.__stock 私有（双下划线开头），外部不能直接改价格、改库存
  • 私有方法：__real_price() 计算折后价 self.__price * Product.discount，只在类内部被调用
  • 实例方法：sell(qty) 卖货——库存够则扣库存、按折后价收款；不够则提示「库存不足！」
  • 类方法：set_discount(d) 用 @classmethod 修改类属性，实现「全场调价」

🔬 商店收银台实验台：点按钮执行 PPT 测试流程

点按钮模拟收银～重置可回到初始状态（手机 2999 元 ×10，Python教材 59 元 ×200，无折扣）。
课堂代码

完整类定义（对照实验台逐行看）

class Product:
    discount = 1.0                      # 类属性：全场折扣

    def __init__(self, name, price, stock):   # 初始化方法
        self.name = name                # 实例属性：公开
        self.__price = price            # 私有属性
        self.__stock = stock            # 私有属性

    def __real_price(self):             # 私有方法：折后价
        return self.__price * Product.discount

    def sell(self, qty):                # 实例方法：卖货
        if qty <= self.__stock:
            self.__stock -= qty
            total = qty * self.__real_price()
            print(f"卖出 {qty} 个{self.name}，收款 {total:.2f} 元")
        else:
            print("库存不足！")

    @classmethod
    def set_discount(cls, d):           # 类方法：全场调价
        cls.discount = d
        print(f"全场折扣已调整为 {int(d*10)}折")
  • 一个类里同时出现了：类属性、实例属性（含私有）、私有方法、实例方法、类方法——对照每行注释确认你都能认出来
  • __real_price 只被 sell 内部调用——这就是「隐藏细节、暴露接口」
  • cls.discount = d 改的是类属性，两个商品对象立即同步生效
课堂代码

测试运行与输出

# 创建商品
phone = Product('手机', 2999, 10)
book  = Product('Python教材', 59, 200)

# 原价销售
phone.sell(2)
book.sell(1)

# 开启八折活动
Product.set_discount(0.8)
phone.sell(3)

# 超量购买
book.sell(200)

输出结果：

卖出 2 个手机，收款 5998.00 元
卖出 1 个Python教材，收款 59.00 元
全场折扣已调整为 8折
卖出 3 个手机，收款 7197.60 元
库存不足！
  • 2999 × 2 = 5998.00（无折扣）；2999 × 0.8 × 3 = 7197.60（八折）——:.2f 保留两位小数
  • book.sell(200)：库存 200 但前面卖掉 1 个只剩 199，200 > 199 → 库存不足
  • 整个过程外部代码从未直接碰过 __price 和 __stock——封装在悄悄保护数据

✏️ 填空

Product 类中：discount 由所有对象共享，它是＿＿属性；name 每个商品各自一份，它是＿＿属性；__price 双下划线开头外部无法直接访问，它是＿＿属性。（三空用空格隔开）

⚠️ 避坑
三个高频翻车点

①私有属性直接访问会报错：phone.__price 抛 AttributeError——价格只能通过 sell 等公开方法间接影响；

②类方法里写 self 会 NameError：@classmethod 的第一个参数是 cls，操作类属性要用 cls.discount；

③忘记库存会变：sell 会扣减 __stock，同一批对象多卖几次后「库存不足」可能提前出现——实验台里点重置再试一遍就能对上 PPT 的输出。

✅ 小结
本章回顾——你现在知道了
