为什么学这个

用户到底输的是「纯数字」「纯字母」还是「乱七八糟」？

写程序经常要验货：注册时验证「用户名只含字母和数字」、填表时验证「手机号全为数字」、处理文本时跳过空白行。这一族以 is 开头的方法就是验货员——它们不改造字符串，只回答一个问题：True（是）还是 False（不是）。

💡 打个比方
数字三兄弟：小圈套大圈

判断数字的三个方法像三个套在一起的圈：isdecimal() 是最里面的小圈，只认十进制数字字符，上标 ² 和汉字「五」都不认，最严格；isdigit() 是中圈，除了 0-9 还认上标数字（如 ²）；isnumeric() 是最大的圈，最宽容——连汉字「五」、罗马数字「Ⅴ」、分数「½」都认。小圈里的都是大圈里的，反之不然。

交互示例

数字三兄弟的包含关系：层层放宽

print("123".isdecimal(), "123".isdigit(), "123".isnumeric())
→ True True True　（纯阿拉伯数字：三兄弟都认）

print("123²".isdecimal(), "123²".isdigit(), "123²".isnumeric())
→ False True True　（上标数字：小圈不认，中圈大圈认）

print("五".isdecimal(), "五".isdigit(), "五".isnumeric())
→ False False True　（汉字数字：只有最大圈认）
外圈 isnumeric()：0-9 ＋ 上标² ＋ 汉字「五」＋ 罗马Ⅴ ＋ 分数½ 中圈 isdigit()：0-9 ＋ 上标² 内圈 isdecimal()：十进制数字（最严格，上标 ² 与汉字「五」都不认）

记忆口诀：圈越大越宽容，判断为 True 的字符越多。处理「用户输入的阿拉伯数字」时用最严格的 isdecimal() 最稳妥。

⚠️ 避坑
空串一律 False，空格会「污染」判断

坑一：空串所有 is 判断都是 False。"".isalpha()、"".isalnum() 都返回 False——isalnum 和 isalpha 更是明确要求非空才可能为 True。判断用户输入前，先想想「他是不是什么都没输」。

坑二：一个空格毁掉全部。"Python 3".isalnum() 是 False，就因为中间混进了一个空格；" 123 ".isdigit() 同理也是 False。读入的输入常带两端空格，验证前先 strip() 一下是好习惯。

坑三：三兄弟别混用。验证「手机号」这类纯阿拉伯数字用 isdecimal() 最严格；如果用 isnumeric()，用户输入「五」也能混过关——这是宽容的代价。

✅ 小结
你现在知道了

六个 is 方法只回答 True/False：isalnum 字母数字、isalpha 纯字母、isspace 纯空白；数字三兄弟是套圈——isdecimal（只认 0-9）⊂ isdigit（加上标）⊂ isnumeric（汉字、罗马数字都认）；空串一律 False、带空格易污染。下一节：让输出变漂亮——format 格式化输出！
