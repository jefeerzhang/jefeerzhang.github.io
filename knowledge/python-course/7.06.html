为什么学这个

写完的数据「不见了」？多半是文件没关

三步曲的第三步最容易被新手省略——「我东西都写进去了，关不关有什么区别？」区别大了：忘关文件，数据可能还堵在缓冲区里没落到磁盘，程序一崩全白写；文件还一直被你的程序占着，别的程序想用都打不开。这一节教你两件事：为什么必须关，以及怎么用 with 语句让 Python 替你自动关，从此告别「忘了 close」。

💡 打个比方
with 像「自动感应门」，手动 close 像「随手关门」

商场的自动感应门（with 语句）：你走进去办完事，人一出来，门自动关上，想忘都忘不了。close() 则像家里那扇随手关的门：理论上你该记得带上，可一旦哪天忘了——冷风（数据丢失、资源占用）就一直往屋里灌。以后的代码，请尽量走「感应门」。

核心概念

为什么要关闭 + with 语句怎么写

  • 关闭原因①——保数据：把缓冲区中还没落盘的数据写入磁盘，确保数据完整性
  • 关闭原因②——还资源：释放操作系统资源，避免文件被长期占用，导致其他程序无法访问
  • 关闭原因③——划界线：关闭后的文件不能再读写，否则触发 ValueError: I/O operation on closed file
  • 语法：文件对象名.close()
  • with 语句：为防止忘记关闭或程序异常导致文件不能正常关闭，建议用 with 保留字打开文件——它通过缩进控制文件状态，缩进结束系统自动调用 close()
  • with 语法：with open(filename, mode, encoding) as 文件对象名: 换行缩进，写文件处理操作

🚪 手动版：忘了就漏风

file = open('abc.txt', 'w',
            encoding='utf-8')
pass
pass
file.close()   # 中间隔很远，
               # 一忙起来就忘了

🚀 自动版：with 语句（推荐）

with open('abc.txt', 'w',
          encoding='utf-8') as file:
    pass
# 缩进一结束，
# 系统自动调用 file.close()
课堂代码

同一个任务，两种写法

# 写法一：手动关闭（三步曲标准写法）
file = open('abc.txt', 'w', encoding='utf-8')
file.write('Hello Python')
file.close()

# 写法二：with 语句（推荐）
with open('abc.txt', 'w', encoding='utf-8') as file:
    file.write('Hello Python')
# 走出缩进块，close 自动完成，想忘都忘不了
  • 写法二的 as file：把 open 返回的文件对象起名叫 file，缩进块内随便用
  • with 块内的代码必须缩进——缩进就是「感应门内的区域」
  • 出了 with 块再访问 file 读写，同样会触发 ValueError（门已经关了）
  • 作业第 1、2 题都建议用 with 写法，交上去的代码更稳、更专业
❓ 测验

对已调用 close() 的文件对象再调用 file.read()，结果是什么？

✏️ 填空

with 语句通过＿＿控制文件状态，缩进结束系统自动调用＿＿() 方法关闭文件。（两空用空格隔开）

⚠️ 避坑
三个高频翻车点

①不 close 就以为写好了：write 的数据先进缓冲区，close 才确保落盘——程序异常退出时缓冲区数据直接丢失，白写；

②关了还想读：close 之后再 read/write 必报 ValueError——「感应门」关了就别伸手，要再操作就重新 open；

③with 块内忘缩进：with … as file: 下一行必须缩进，不缩进直接 IndentationError——缩进块就是文件「开着」的范围。

✅ 小结
你现在知道了

关闭文件有三个理由：缓冲区数据落盘保完整、释放系统资源不被占用、关闭后不可再读写（否则 ValueError）。with open(...) as 文件对象: 通过缩进控制文件状态，缩进结束自动 close，是最推荐的写法。至此三步曲的「打开」「关闭」都齐了——下一节讲第二步的写：write 与 writelines。
