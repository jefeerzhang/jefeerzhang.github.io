为什么学这个

有的东西每人一份，有的东西全班共享一份

班里每个同学都有自己的名字（各不相同、各自保管），但全校共用同一块校名牌（改一次、全校生效）。对象的属性也一样：上一节的 self.name 是每个对象独立一份的「实例属性」，而直接写在类里的属性是全体对象共享的「类属性」。分不清这两种，后面读代码时就会出现「我明明只改了一个对象，怎么大家都变了？」这种灵异事件——这一节就是给属性「查户口」的。

💡 打个比方
实例属性像「校服上绣的名字」，类属性像「校门口的校名牌」

校服名字（实例属性）每人绣各人的，绣在哪件校服上就是哪件的事，别人管不着；校名牌（类属性）挂在校门口，属于学校本身，全校师生抬头都能看到它——学校改一次牌子，所有师生「看到的内容」同时更新。但如果你偷偷在自己校服上也别了一枚写着别名的胸牌，那你看到的就只剩自己的胸牌了——这就是下一节避坑里讲的「遮住」。

核心概念

两种属性，四个维度对照

🔀 点击切换两种属性，对照四个维度

定义位置在 __init__ 方法内，以 self.属性名 = 值 定义
归属每个对象独立拥有各自的值，互不影响
访问方式只能通过 对象名.属性名 访问（用类名访问会报错）
典型例子self.name = name——每只狗有自己的名字
定义位置在类中直接定义（不在任何方法内），写法就是 属性名 = 值
归属所有对象共享同一个值，一处修改全体生效
访问方式类名.属性名 和 对象名.属性名 都能访问
典型例子species = '犬科动物'——所有狗共同的物种

🔬 一改全改实验台：改 Dog.species，看 d1.species 跟不跟着变

先创建对象 d1，再执行 PPT 的两条打印，然后改类属性试试。
课堂代码

PPT 原例：Dog 类的两种属性

class Dog:
    species = '犬科动物'          # 类属性：写在类中、方法外

    def __init__(self, name):
        self.name = name         # 实例属性：写在 __init__ 内

d1 = Dog('旺财')

print(Dog.species, d1.species)   # 类名和对象名都能访问类属性
print(d1.name)                   # 实例属性只能通过对象访问

输出结果：

犬科动物 犬科动物
旺财
  • species 定义在类里、所有方法之外——它是类属性，Dog.species 和 d1.species 读到的是同一份
  • name 在 __init__ 里挂在 self 身上——它是实例属性，只有 d1.name 能访问
  • 实例化时 __init__ 执行一次，实例属性就「刻」在对象身上一份；类属性始终只有一份，挂在类身上
  • 把 Dog.species = '犬科' 之后，d1.species 也变成 '犬科'——共享、一改全改
❓ 测验

接 PPT 原例，执行 Dog.species = '犬科' 之后，print(d1.species) 的输出是？

✏️ 填空

每个对象各自拥有、互不影响的是＿＿属性；所有对象共享同一个值、一处修改全体生效的是＿＿属性；类属性既可以用 类名.属性名 访问，也可以用 ＿＿.属性名 访问。（三空用空格隔开）

⚠️ 避坑
三个高频翻车点

①用类名访问实例属性：Dog.name 报 AttributeError——实例属性挂在对象身上，只能 d1.name 这样访问；

②在 __init__ 里漏写 self.：name = name 只是方法内的普通局部变量，函数一结束就消失——必须写 self.name = name 才是实例属性；

③给对象单独赋值会「遮住」类属性：执行 d1.species = '小汪' 后，d1 身上多了一份自己的实例属性，以后 d1.species 读的是自己那份，类属性再改也影响不到它。

✅ 小结
你现在知道了

实例属性在 __init__ 中以 self.属性名 定义，每个对象独立拥有各自的值，只能通过对象访问；类属性在类中直接定义（不在方法内），所有对象共享同一个值，类名和对象名都能访问，一处修改全体生效。下一节：方法也分三种——实例方法、类方法、静态方法，和今天的属性划分正好呼应。
