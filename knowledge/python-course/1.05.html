为什么学这个

同是高级语言，凭什么分两大门派？

你写的 Python 代码、程序员写的 C 代码，计算机其实都一个字都看不懂——它只认 0 和 1。那代码是怎么变成计算机能执行的动作的？关键就在于"翻译"方式的不同。搞懂这一节，你才能明白：

  • 为什么 Python 写一行就能马上看到结果，而 C 语言要先"编译"才能运行？
  • 为什么说 Python 属于脚本语言 / 解释型语言（第一章作业第 2 题就考这个）？
  • 为什么 Python 开发效率高，但运行速度却不如 C / C++？
💡 打个比方
翻译一本英文书，有两种翻法

编译型 = 找翻译公司一次性把整本书翻完，装订成中文版直接发行。读者（计算机）拿到的就是成品，读起来飞快；但如果原文改了一个字，就得整本重新翻译。

解释型 = 请一位同声传译坐在旁边，读一句、翻一句、执行一句。改了原文，下次照读不误、非常灵活；但每次阅读都得带着译员，速度自然慢一些。

核心概念

两种翻译方式，两条技术路线

  • 编译型语言（静态语言）：源代码经编译器（Compiler）一次性翻译成目标代码（机器码），之后直接执行，运行效率高。典型代表：C、C++、Go。（Java 常被归为「半编译半解释」：先编译成字节码，再由虚拟机解释执行。）
  • 解释型语言（脚本语言）：源代码由解释器（Interpreter）逐行翻译，边翻译边执行（边译边跑），开发灵活、跨平台方便。典型代表：Python、JavaScript、PHP。
  • 一句话记忆：编译型"先翻译完再吃饭"，解释型"边做边吃"。

编译型 · 以 C 为例

编译器一次性翻译 → 生成机器码 → 再运行

解释型 · 以 Python 为例

解释器逐行翻译 → 每行马上执行
💡 观察：左边必须"全部翻译完"才出现输出；右边每翻译一行，输出就立刻多一行。

⚠️ 避坑
"解释型 = 完全不翻译"？不对

新手容易以为 Python 代码是"直接被机器读懂的"。其实 Python 也会先把源代码编译成字节码（.pyc 文件），再由 Python 虚拟机执行——只是这一步对使用者完全透明、自动完成，不需要像 C 那样手动编译。

另外，"解释型慢"是相对的：在 AI、数据分析场景中，Python 的核心计算都由 C/C++ 编写的底层库（NumPy、PyTorch）完成，整体速度并不差。别用"慢"一个字否定 Python。

我刚学了"编译型语言和解释型语言"的概念。请：1）用一个生活类比帮我再解释一遍两者的区别；2）每种类型各举 3 个代表语言及代表作品；3）出 2 道单选题考我，等我作答后再公布答案。
🔧 试一试：亲眼看看"边解释边执行"（4 分钟）
  1. 按作业第 6 题的要求，在你的电脑上装好 Python（或打开 Anaconda）。
  2. 按 Win + R 输入 cmd 打开命令行，输入 python 回车，进入交互模式（出现 >>> 提示符）。
  3. 输入 1 / 2 回车——不等任何"编译"步骤，立刻得到 0.5。这就是解释型语言"边译边跑"的直接体验。
  4. 再输入一行故意写错的代码，比如 print(abc——你会看到解释器立刻报出 SyntaxError，这段代码一行都不会执行——语法错误在「编译成字节码」的阶段就被整段拦下。想看「先执行前面、到出错那行才中断」，要写运行时异常，例如 print(1/0)——这才是解释型「边译边跑」的表现。
✅ 小结
你现在知道了

高级语言必须"翻译"成机器语言才能执行：编译型一次性翻译完再运行（C/C++），解释型逐行翻译边译边跑（Python/JavaScript）。Python 属于解释型（脚本）语言，开发灵活、跨平台，代价是运行速度相对慢——但它依然是 AI 时代最热门的语言。下一节，我们看看编程语言的"流行度榜单"。
