为什么学这个

函数调用自己？不看着它跑一遍，你永远觉得玄

上一节知道了递归要有递归链条和基项。但很多人背得出口诀，一写代码还是晕——因为看不见计算机内部发生了什么。这一节我们把 factorial(5) 的执行过程一层层拆开给你看：递推时怎么「层层拆解」，回溯时怎么「步步返回」。看懂这一节，后面两节的递归代码就只是「照着流程翻译」而已。

💡 打个比方
递归像「食堂传餐盘」：往下传是递推，往上端回是回溯

5 号窗口的同学要算 5!，他不直接算，而是在单子上写「4! 是多少？」传给 4 号窗口；4 号又写「3! 呢？」传给 3 号……一路传到 0 号窗口，他手里有现成答案「0! = 1」（这就是基项，不用再传了）。然后答案开始往回端：1 号拿到 1，算出 1×1=1 递上去；2 号算出 2×1=2；……5 号拿到 24，算出 5×24=120，完成任务。往下传叫递推，往回端叫回溯——递归 = 递推 + 回溯。

核心概念

以 factorial(5) 为例的两个阶段

  • 递推阶段（Recursion）：问题一层层拆小——factorial(5) → 5 × factorial(4) → 4 × factorial(3) → … 每次调用自身时参数一定要变化（n 在变小），否则永远传不到底
  • 基项触发：拆到 n = 0 时命中基项 if n==0: return 1，停止继续调用——「传餐盘」到此为止
  • 回溯阶段（Backtracking）：答案步步返回——factorial(0)=1 → factorial(1)=1×1=1 → factorial(2)=2×1=2 → … → factorial(5)=5×24=120
  • 核心逻辑一句话：递归 = 递推（层层拆解）+ 回溯（步步返回）

📌 小提示：PPT 流程示意以「基线 n=1」为例；本页按课堂代码 if n==0: return 1 的实际语义演示，基项在 n=0 处触发——两种写法都正确，只是基项选的位置不同。

课堂代码

边看实验台，边对照代码

def factorial(n):
    if n == 0:
        return 1          # 基项：拆到这里就停
    else:
        return n * factorial(n-1)   # 递归链条：参数 n 变小

print(factorial(5))

输出结果：

120
  • 前 5 次调用都在走 else 分支（递推），每次 n 减 1
  • n = 0 时走 if 分支返回 1（基项），此后不再有新的调用
  • 之后的计算全部发生在「返回的路上」（回溯）：1×1 → 2×1 → 3×2 → 4×6 → 5×24
交互示例

换一个问题再跑一遍：字符串逆序 rev(s)

def rev(s):
    if len(s) == 0:
        return s                      # 基项：空串直接返回
    else:
        return rev(s[1:]) + s[0]      # 链条：去掉头，接到尾

print(rev("12345"))

输出结果：

54321
  • 递推：rev("12345") → rev("2345") + '1' → rev("345") + '2' → … → rev("") 触发基项
  • 回溯："" + '5' = "5" → "5"+"4" = "54" → … → "5432"+"1" = "54321"
  • 和阶乘对照：链条都是「问题变小」，基项都是「小到不用再拆」——结构完全同构
❓ 测验

按课堂代码 if n==0: return 1，factorial(3) 在回溯阶段最先算出的是哪个值？

✏️ 填空

递归问题必须满足两大特征：＿＿（后一项依赖前一项）和＿＿（不需要再递归的停止点）；递归的执行分为＿＿（层层拆解）和＿＿（步步返回）两个阶段。（四空用空格隔开）

⚠️ 避坑
三个高频翻车点

①忘写基项：只有链条没有停止点，递归会一直拆下去，最后抛 RecursionError: maximum recursion depth exceeded（超过最大递归深度）；

②链条参数不变：写成 return n * factorial(n)，n 永远不变，同样拆不到基项——参数必须向基项「靠近」；

③把递推当回溯：乘法发生在返回的路上，不是调用的时候。先拆到底、再步步往回乘——顺序搞反，手算结果就对不上。

✅ 小结
你现在知道了

递归执行分两阶段：递推（层层拆解，参数向基项靠近）+ 回溯（步步返回，计算发生在返回路上）；基项命中后停止调用；递归链条和基项缺一不可。下一节：把这套流程翻译成阶乘代码。
