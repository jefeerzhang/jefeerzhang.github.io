为什么学这个

文件写进去了，怎么「读出来」才算会用？

上一节你把《悯农》和成绩表写进了文件，但数据存进去不是目的，用的时候要能读出来。Python 提供三个读文件方法：read()、readline()、readlines()——一个读全部、一个读一行、一个读成列表。选错方法，轻则浪费内存、重则程序卡死；作业第 2 题读 scores.txt 求平均分，就要挑对方法。

💡 打个比方
read 像「整本书复印」，readline 像「一次读一行」，readlines 像「撕成一张张纸条装进袋子」

read() 一口气把整本书复印到手——省事，但书越厚占的地方越大；readline() 每次只读一行，读多少占多少，再厚的书也不怕；readlines() 把全书按行撕成纸条装进一个袋子（列表），每张纸条就是一行，方便按条处理，但整本书还是都在袋子里。

核心概念

三个方法对比一览

方法返回值内存占用适合场景
read(size) 字符串：读取 size 个字符；无参数或 size 为负数则读取全部内容 高（一次性读完） 小文件整体读取
readline() 字符串：读取一行内容（包含末尾的换行符 \n） 低（逐行读取） 大文件逐行处理
readlines() 列表：读取所有行，每行是列表的一个元素（含 \n） 中（一次性读完） 中等文件按行操作
  • 文件对象本身也是可迭代对象：for line in file 可以逐行遍历，效果类似 readline 的循环版，内存占用低
  • 读取会推动文件指针后移（下一节细讲）：连续调用是接续着读，不是每次都从头读
课堂代码

PPT 原例：三方法连用，指针接续读

《悯农》.txt 已含四行诗。同一段代码里连用三个方法：

with open('《悯农》.txt', 'r', encoding='utf-8') as file:
    print(file.readline())
    print(file.read(3))
    print(file.readlines())

输出结果：

锄禾日当午，

汗滴禾
['下土。\n', '谁知盘中餐，\n', '粒粒皆辛苦。\n']
  • readline() 读走第一行「锄禾日当午，\n」——行末含换行符，print() 又补一个换行，所以下面多出一个空行
  • read(3) 从第二行开头接着读 3 个字符「汗滴禾」——指针接续，不是从头读
  • readlines() 把剩下的三行装进列表返回，每个元素都带着 \n
交互示例

for line in file：逐行遍历最优雅

with open('《悯农》.txt', 'r', encoding='utf-8') as file:
    for line in file:
        print(line, end='')

输出结果：

锄禾日当午，
汗滴禾下土。
谁知盘中餐，
粒粒皆辛苦。
  • 文件对象就是可迭代对象，for 每轮拿到一行（含 \n）
  • print(line, end='') 用 end 参数把 print 自带的换行关掉——因为 line 末尾已经有 \n 了，不然会隔行打印
  • 处理大文件首选这种方式：一行一行读，内存稳得住
❓ 测验

对一个 4 行的文件执行 file.readlines()，返回值是？

✏️ 填空

读取整个文件、返回一个字符串，用＿＿()；读取所有行、返回一个列表，用＿＿()；每次读一行、内存占用最低，用＿＿()。（填方法名，用空格隔开）

⚠️ 避坑
四个高频翻车点

①print 输出隔行打印：readline / for line 读到的行末尾自带 \n，print 又加一个换行——处理前先 line.strip() 或 print 时用 end=''；

②readlines 的元素直接当数字算报错：元素是带 \n 的字符串，要先 strip() 去掉换行、再拆分转换；

③大文件用 read() 一口吞：内存占用高，几百 MB 的日志文件会把程序撑垮——改用 readline 或 for line in file；

④读完一次再读是接续不是重来：连续两次 readline 读到的是第一行、第二行，想重读得等下一节的 seek(0)。

✅ 小结
你现在知道了

read(size) 读取指定字符数（无参读全部）、返回字符串，适合小文件；readline() 一次读一行（含 \n）、内存占用低，适合大文件；readlines() 返回每行为元素的列表，适合中等文件按行操作；for line in file 是逐行遍历的首选写法；print 出现空行是因为行末自带 \n。下一节揭秘：读取时在背后默默移动的文件指针 tell 与 seek。
