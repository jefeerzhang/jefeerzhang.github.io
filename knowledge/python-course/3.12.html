为什么学这个

官方推荐的格式化方式：少写一半字

上一节的 format 已经很好用了，但每次都要在字符串后面补一句 .format(a, b)，变量离大括号远，读起来要来回对照。f-string 是 Python 3.6+ 引入的特性，也是目前官方推荐的字符串格式化方式：在字符串引号前加一个小写字母 f，大括号里直接写变量甚至表达式——代码更简洁、可读性更高、执行效率也优于传统格式化方式。以后你写自己的项目，基本只用它。

💡 打个比方
format 像填表上交，f-string 像现场直播

format 是「填表上交」：字符串是一张表格，你要把所有数据收集齐，最后一起交到 .format() 柜台统一分发；f-string 是「现场直播」：大括号里直接写变量、直接做运算（{a+b}），边写边算、当场出结果，不用排队交表。格式控制符号两台机器通用——冒号后面的那套「装饰要求」完全一样。

核心概念

加个 f，大括号里随便写

  • 用法：在字符串引号前加小写字母 f，如 f"..."
  • 大括号里可以直接写变量：f"{a}"
  • 还可以直接写表达式：f"{a+b}"、f"{a/b:.2f}"——边写边算
  • 格式控制符号与 format 完全一致：:>、:<、:^、:e、:.2f、:0>5 等原样通用
a, b = 2, 3
print(f"{a}+{b}={a+b}")                      → 2+3=5
print(f"{'Python':*>10}{'123':-<7}")         → ****Python123----
print(f"{a:^3}+{b:^3}={a+b:^3}")             → 2 + 3 = 5
print(f"{a}/{b}等于{a/b:e}, 约等于{a/b:.2f}") → 2/3等于6.666667e-01, 约等于0.67

对照上一节：同样的输出，format 要写 "{}+{}={}".format(a, b, a+b)，f-string 只要 f"{a}+{b}={a+b}"——少写一整段柜台调用。

交互示例

同一任务两种写法，同屏对照

a, b = 2, 3
print("{}+{}={}".format(a, b, a+b))
print("{:*>10}{:-<7}".format('Python', '123'))
print("{}/{}等于{:e}, 约等于{:.2f}".format(a, b, a/b, a/b))
2+3=5
****Python123----
2/3等于6.666667e-01, 约等于0.67

痛点：写完大括号还要回头数参数顺序，变量和占位符隔得远。

a, b = 2, 3
print(f"{a}+{b}={a+b}")
print(f"{'Python':*>10}{'123':-<7}")
print(f"{a}/{b}等于{a/b:e}, 约等于{a/b:.2f}")
2+3=5
****Python123----
2/3等于6.666667e-01, 约等于0.67

输出一模一样，但大括号里就地取材、直接运算——变量在哪，占位就在哪，不用来回对照。

❓ 测验

f-string 是从 Python 哪个版本开始引入的？

✏️ 填空

使用 f-string 时，需在字符串引号前加字母 ____，大括号内的内容才会被求值。

⚠️ 避坑
漏了 f，一切照旧

坑一：漏写 f 不报错，但大括号原样输出。print("{a}+{b}") 会老老实实打印 {a}+{b} 这七个字符——没有 f，Python 就把大括号当普通字符。程序不报错、结果却不对，这种「静默翻车」最隐蔽，输出怪怪的先检查 f。

坑二：大括号里不能用反斜杠转义（Python 3.12 之前的版本），f"{'don\'t'}" 会直接报错。需要引号时，外层和内层用不同的引号：f"{'Python':*>10}" 外双内单。

坑三：别为了炫技把复杂逻辑塞进大括号。f-string 适合放简单变量和短表达式（如 {a+b}、{a/b:.2f}）；一整段 if-else 塞进去，可读性反而崩了——简洁是它的初衷。

✅ 小结
你现在知道了

f-string 是 Python 3.6+ 引入、官方推荐的格式化方式：引号前加 f，大括号里直接写变量和表达式（{a+b}），格式控制符号与 format 完全通用；它更简洁、可读性更高、执行更快；漏写 f 大括号会原样输出、3.12 之前版本大括号里不能用反斜杠。字符串方法与格式化到此全部学完，下一节进入新大陆：列表的定义与特性！
