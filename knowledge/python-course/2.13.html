为什么学这个

小数不"老实"，先给它立规矩

浮点数（float）就是带小数部分的数，但它有几个"不老实"的地方，初学时最容易被坑：

  • 10. 也是浮点数——type(10.) 得到 <class 'float'>，只要带小数点就是 float
  • 支持科学计数法：5e3 就是 5000.0，-5E-3 就是 -0.005
  • 浮点数用二进制存储，可能导致精度问题：0.1 + 0.2 竟然不等于 0.3！

这一节就带你亲眼看看这些"惊喜"，并学会正确应对。

💡 打个比方
二进制存小数 = 用 1/2、1/4、1/8 凑零钱

计算机存小数只能用 2 的负次幂（0.5、0.25、0.125……）去"凑零钱"。十进制的 0.1 在二进制里是无限循环小数，就像让你用 5 角、2 角 5 分、1 角 2 分 5 厘……永远凑不出整 1 角，只能凑到非常接近为止。所以 0.1 存进电脑里其实是个"近似值"——这不是 Python 的 bug，而是所有编程语言的通病。

核心概念

浮点数的三个"性格"

  • 带点就是 float：type(10.) → <class 'float'>。小数点后哪怕不写数字，也是浮点数。
  • 科学计数法照单全收：5e3 表示 5×10³ = 5000.0；-5E-3 表示 -5×10⁻³ = -0.005。e 或 E 都行，结果是 float。
  • 存储精度有极限：0.1 == 0.1000000000000001 → False，但 0.1 == 0.10000000000000001 → True——说明 float 大约有 15–17 位有效数字的精度，再往后的差异就"看不出来"了。

🔍 点击切换，看两组经典演示：

print(5e3)     # 5×10³
print(-5E-3)   # -5×10⁻³
print(type(10.))

输出：5000.0、-0.005、<class 'float'>　—— 科学计数法结果是 float，10. 带个小数点也是 float

print(0.1 == 0.1000000000000001)
print(0.1 == 0.10000000000000001)
print(0.1 + 0.2)

输出：False、True、0.30000000000000004　—— 0.1 的存储精度极限约 16 位小数；0.1+0.2 的"零头"正是二进制近似存储留下的痕迹

实战演示

为什么 0.1 + 0.2 ≠ 0.3？

print(0.1 + 0.2)          # 输出：0.30000000000000004
print(0.1 + 0.2 == 0.3)   # 输出：False！

原因拆解：计算机用二进制存小数，十进制的 0.1 换算成二进制是无限循环小数（0.000110011…），内存空间有限，只能截断近似存储。两个"近似值"相加，误差就露馅了——于是得到了 0.30000000000000004。

💡 记住：这是所有编程语言的通病（C、Java、JavaScript 都一样），不是 Python 出了 bug。二进制存储浮点数导致精度问题，是浮点数的天性。

❓ 测验

print(0.1 + 0.2) 的输出是？

✏️ 填空

5e3 的值是＿＿；而 -5E-3 的值是 -0.005。（写 5000.0 或 5000 均可）

⚠️ 避坑
千万别用 == 直接比较两个浮点数！

0.1 + 0.2 == 0.3 的结果是 False——用 == 判断浮点数相等是经典大坑。正确姿势有两种：

① 用 round() 四舍五入到合理位数后再比较：

round(0.1 + 0.2, 10) == 0.3   # True

② 或判断两数之差的绝对值是否小于一个很小的数：

abs(0.1 + 0.2 - 0.3) < 1e-9   # True

两种方法都在说同一件事：浮点数只谈"足够接近"，不谈"完全相等"。

🔧 试一试：亲眼见证精度陷阱（3 分钟）
  1. 打开命令行输入 python 进入交互模式。
  2. 输入 print(0.1 + 0.2) 回车——看看是不是真的输出 0.30000000000000004。
  3. 输入 0.1 == 0.10000000000000001 回车——输出 True？想想这说明了 0.1 的存储精度极限在哪里。
  4. 再用正确姿势试试：round(0.1 + 0.2, 10) == 0.3 和 abs(0.1 + 0.2 - 0.3) < 1e-9，确认都返回 True。
✅ 小结
你现在知道了

浮点数带小数点即是 float（10. 也是），支持科学计数法（5e3=5000.0、-5E-3=-0.005）。由于二进制存储，0.1 这类小数只能近似保存，精度极限约 15–17 位有效数字（sys.float_info.dig 的值是 15），于是 0.1 + 0.2 得到 0.30000000000000004——这是所有编程语言的通病。比较浮点数要用 round() 或 abs(a-b) < 1e-9，别用 ==。下一节：算术运算符与增强赋值。
