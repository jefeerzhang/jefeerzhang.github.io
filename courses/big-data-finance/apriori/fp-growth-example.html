FP-Growth 条件模式基与条件 FP 树：完整递归示例

先看对比：Apriori 和 FP-Growth 差在哪

两个算法目标相同——找出满足最小支持度的频繁项集，但思路完全不同。下表用同一组维度对比，看完再读后面的递归示例会更清楚 FP-Growth 省在哪里。

维度AprioriFP-Growth
核心思路逐层生成候选项集，每一层都扫描全表计数把数据压缩成一棵 FP 树，再在树上递归提取条件模式基
是否生成候选是。k 项集由 (k−1) 项集两两连接生成，再剪枝否。不枚举候选，直接在树上读路径
扫描数据次数每一层扫一次全表；n 个商品最多扫 n 次只扫两次：第一次建头表，第二次建树
内存占用候选项集可能爆炸式增长，尤其支持度低时整棵树压缩在内存里，相同前缀的路径共享节点
适合数据稀疏、项集短、支持度较高的数据集稠密、重复模式多的数据集；树塞不进内存时反而不如 Apriori
主要代价多次 I/O + 候选生成与剪枝的计算建树和递归的内存开销，条件模式基可能反复拷贝
结果是否相同相同——在相同最小支持度下，两个算法找出的频繁项集集合完全一致，只是路径不同

下面用 5 笔交易走完 FP-Growth 的全过程：建树，再逐个商品提取条件模式基、建立条件 FP 树、递归，最后得到全部 18 个频繁项集。每一步都可以手算复核。

2. 建立 FP 树：扫描两遍数据

一个类比：很多人走山路

  • 每笔交易看成一个人走的一条路线。
  • 路线开头相同的人，就走同一段路。
  • 走到岔口，大家才各走各的。
  • 每段路上立一块牌子，记录走过的人数。

FP 树就是这张路线图。树上的 f(4) 表示有 4 笔交易经过 f 这个节点。

FP 树的用处

  • 只扫描两遍数据。第一遍数商品，第二遍建树。之后的挖掘只在树上进行。
  • 不生成候选组合。Apriori 每一层都要先列出所有候选组合，再回头扫描数据逐个检查。FP-Growth 直接沿着树上的路径找组合。
  • 头表相当于目录。头表用节点链把同名节点串起来。比如要找所有 m，顺着链就能走到每个 m 节点，不必遍历整棵树。

3. 递归的方法

核心思路只有一句：

固定一个商品 x，把所有通向 x 的路径单独取出来，看哪些商品经常和 x 一起出现。

对当前树中的每个商品 x，按头表从后往前依次做四步：

  1. 输出项集。把树中所有 x 节点的计数相加，就是 x 与已固定商品组成的项集的支持度。
  2. 提取条件模式基。对每个 x 节点，取根节点到它之前的路径（前缀路径），并把该节点的计数作为这条路径的权重。
  3. 建立条件 FP 树。按权重汇总前缀中每个商品的计数，删去小于 3 的商品，用剩下的路径建一棵更小的树。
  4. 递归。条件 FP 树不为空时，就在这棵树上重复这四步，并把 x 加入已固定的商品；条件 FP 树为空时，这一支结束。

伪代码：

挖掘(树 T, 已固定的商品 α):
    按头表从后往前，依次处理每个商品 x:
        输出 {x} ∪ α 及其支持度
        提取 x 的条件模式基，建立条件 FP 树 T_x
        如果 T_x 不为空:
            挖掘(T_x, {x} ∪ α)

条件 FP 树里的计数是条件支持度：只统计同时包含已固定商品的交易，通常小于该商品的原始计数。

汇总后 f = 2、c = 2、a = 1，都小于 3。条件 FP 树为空，这一支结束。

结果：{b}: 3

4.4 a：与 m 分支里的子树相同

树中只有一个 a 节点，计数为 3，所以 {a}: 3。条件模式基只有 f → c（权重 3），条件 FP 树为 f(3) → c(3)。

在这棵树上：处理 c 得到 {c, a}，再处理 f 得到 {f, c, a}；处理 f 得到 {f, a}。

结果：{a}、{f, a}、{c, a}、{f, c, a}，计数均为 3。

4.5 c：根节点下的空前缀

树中有两个 c 节点：f 下方的 c(3) 和根节点下方的 c(1)，所以 {c}: 4。

根节点下方的 c(1) 前面没有商品，不产生条件模式，只计入 {c} 的支持度。条件模式基只有 f（权重 3），条件 FP 树为 f(3)。

结果：{c}: 4、{f, c}: 3

4.6 f：没有前缀

f 只在根节点下方出现，没有前缀。

结果：{f}: 4

6. 为什么不重复、不遗漏

在顺序 f > c > a > b > m > p 下，每个项集里排在最后的商品是唯一确定的，这个项集就由那个商品的分支负责产生：

项集排在最后的商品产生路径
{c, p}pp 分支 → c
{f, c, a}aa 分支 → c → f
{f, c, a, m}mm 分支 → a → c → f

每个项集只属于一个分支，所以不会重复；每个分支都穷举了它的所有前缀组合，所以不会遗漏。FP-Growth 的"增长"，就是在已固定的商品前面不断加入新商品，让短组合逐步变长。

7. 手算常见错误

错误正确做法
把每条前缀路径都当作 1 笔交易用节点计数作为路径权重
在条件树里沿用原始计数在条件模式基中按权重重新计数
把节点下方的商品也放进条件模式基只取从根节点到该节点之前的前缀
漏算根节点下方的节点空前缀不进入条件模式基，但节点计数要计入支持度
只挖一层就停条件 FP 树不为空，就继续递归

FP-Growth 只负责找出频繁项集。关联规则要在这些项集的基础上，再按置信度和提升度生成。
