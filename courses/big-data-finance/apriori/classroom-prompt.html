用 Agent 分析 Groceries：课堂演示提示词

教师使用方法

两种情况都用这一份文件。

在仓库里演示：在本模块 02_Agent关联分析实操/ 目录向 Agent 输入：

读取 课堂演示提示词.md，执行其中「可复制的提示词」，从第一阶段开始。

如果从课程总目录 大数据金融/ 启动，使用 02_Agent关联分析实操/课堂演示提示词.md。工作目录自动识别为本模块目录，结果仍写到本模块的 交付/。

发给学生：只发这一份 Markdown，或只发「可复制的提示词」那一段。学生不需要本仓库的任何其他目录。Agent 会在学生桌面上建 Groceries关联分析/（含 数据/、交付/）并在那里工作，不碰仓库目录。

本提示词只规定分析任务，没有预填分析结论。运行时由 Agent 计算结果。

提示词内含多个 CSV 下载地址，包括国内可用的 CDN 节点与 GitHub 加速镜像。学生本地没有 数据/groceries.csv 时，Agent 会依次尝试并校验，教师不需要另外分发数据文件。若全班都无法下载，把 CSV 随课程材料直接发给学生，学生放入 数据/ 后用同一提示词即可。

可复制的提示词

点击右上角按钮复制，粘贴给 Agent 即可开始：

你是我的数据分析助教。我正在给学生演示：如何用自然语言驱动 Agent，对真实购物篮数据完成关联规则分析。请实际读取文件、编写并运行 Python 代码，不要只给操作建议或代码模板。

### 数据与执行范围

- 先确定工作目录，再开始任何分析。按以下顺序判定，命中即停止：
  1. 当前工作目录下已有 `数据/groceries.csv`，就把当前工作目录当作工作目录。
  2. 当前工作目录包含本提示词（文件名 `课堂演示提示词.md`）且目录名以 `02_Agent关联分析实操` 开头，就把当前工作目录当作工作目录，这是教师仓库内演示的情形。
  3. 当前工作目录下存在 `02_Agent关联分析实操/课堂演示提示词.md`，就把该 `02_Agent关联分析实操/` 子目录作为工作目录，这是从课程总目录 `大数据金融/` 启动的情形。
  4. 其他情形（从桌面启动、或把本提示词直接粘给你、或目录里没有任何相关文件），在用户桌面新建 `Groceries关联分析/` 作为工作目录，内含 `数据/` 与 `交付/` 两个子目录。桌面用 `Path.home() / "Desktop"` 定位；不存在时试 `Path.home() / "OneDrive" / "Desktop"`；两者都不存在就报告实际探测结果并问我，不要自行选别的盘或路径。
- 工作目录确定后，数据文件为 `<工作目录>/数据/groceries.csv`，代码与结果写入 `<工作目录>/交付/`；按需创建这两个子目录。不要在桌面根目录或其他文件夹散落文件。
- 按以下顺序取数：
  1. 数据文件已存在时，先按第 3 项完成四项校验；通过后使用，不得覆盖。已有文件校验失败时报告实测值并暂停，请我核对文件，不自动下载替换。
  2. 文件缺失时，按顺序尝试下列地址，每次先将响应内容读入内存，按第 3 项校验，四项全部通过后才写入 `数据/groceries.csv` 并停止尝试。这些地址均用于获取同一份 CSV，内容以校验结果为准；前三个不经过 GitHub 主域名，国内网络优先试它们：
     - https://fastly.jsdelivr.net/gh/stedy/Machine-Learning-with-R-datasets@master/groceries.csv
     - https://gcore.jsdelivr.net/gh/stedy/Machine-Learning-with-R-datasets@master/groceries.csv
     - https://cdn.jsdelivr.net/gh/stedy/Machine-Learning-with-R-datasets@master/groceries.csv
     - https://ghfast.top/https://raw.githubusercontent.com/stedy/Machine-Learning-with-R-datasets/master/groceries.csv
     - https://gh-proxy.com/https://raw.githubusercontent.com/stedy/Machine-Learning-with-R-datasets/master/groceries.csv
     - https://raw.githubusercontent.com/stedy/Machine-Learning-with-R-datasets/master/groceries.csv
     用 `urllib.request` 或 `requests` 依次请求，每个地址设 30 秒超时。请求失败、内容无法解析或任一校验不符，都记下该地址的错误或实测值，再试下一个地址；HTTP 请求成功不代表文件可用，未通过校验的内容不写入目标文件。
  3. 四项校验基准：文件 500843 字节；9835 笔交易；169 个不同商品类别；SHA-256 为 `ff1be892fd6b9b57d1a7bc50de067798963dda607619645988b21789bf23ae3b`。基于原始字节计算文件大小和哈希，并用 UTF-8 解码、按无表头 CSV 解析后统计交易数与类别数；四项全部通过才进入分析，不修改数据凑数。校验失败时，已有文件按第 1 项暂停处理，新下载的响应按第 2 项继续尝试。
  4. 全部地址均未通过请求与校验时，列出每个地址的错误或实测值，暂停并请我把 `groceries.csv` 放到 `<工作目录>/数据/`，重新校验通过后再继续。不用模拟数据，也不凭记忆生成数据。
  5. 报告里写明以下数据来源、引用，以及本次实际下载地址和四项校验结果；若使用已有文件，写明本地路径，实际下载地址未知时如实标注，不把来源链接冒充本次下载记录。学生无需另取 `README.md`；教师端的模块 `README.md` 仅作补充：
     - 数据说明：arules 官方将 Groceries 描述为一家食品杂货店连续 30 天的真实收银交易。官方说明：https://mhahsler.github.io/arules/reference/Groceries.html 。
     - CSV 来源：Machine-Learning-with-R-datasets 仓库提供的镜像，原始地址为 https://raw.githubusercontent.com/stedy/Machine-Learning-with-R-datasets/master/groceries.csv 。
     - 官方列示的论文引用：Michael Hahsler, Kurt Hornik, and Thomas Reutterer (2006). Implications of probabilistic data modeling for mining association rules. In *From Data and Information Analysis to Knowledge Engineering*, pp. 598–605. Springer-Verlag.
- CSV 无表头，每行是一笔交易，逗号分隔商品类别，各行长度不同。使用 `csv.reader` 或等价方法读取，第一行必须保留。
- 原始 CSV 保持不变。分析代码和结果保存到工作目录的 `交付/`，仅保留 `关联分析.py`、`关联规则.csv`、`分析报告.md`。脚本位于 `交付/`，数据位于其上一级目录下的 `数据/`，使用 `Path(__file__).resolve().parent.parent / "数据" / "groceries.csv"` 定位输入；输出写入 `Path(__file__).resolve().parent`，确保换工作目录后仍可复跑。
- 优先使用现有 Python 环境。缺少依赖时说明情况，征得同意后再安装，不擅自修改全局环境。
- 用中文讲解；商品名保留英文，并在展示时补中文释义。所有数值来自实际执行，清楚区分已执行与未执行的检查。

### 演示节奏

按以下四个阶段执行。每阶段开始前，用两三句话说明目标和做法；执行后展示关键结果，解释给初学者听。**每阶段结束暂停，等待我回复「继续」再进入下一阶段。**

### 第一阶段：认识并检查数据

先确认数据已经就位：使用已有的工作目录，或按「数据与执行范围」新建工作目录并下载、通过四项校验。开场报一句工作目录的绝对路径。然后展示前 5 笔交易，说明一行代表什么。统计交易数、不同商品类别数、商品类别出现总次数，以及每笔交易的商品类别数的最小值、最大值和平均值。

检查空交易、空商品名和同一交易内重复类别。展示实际交易数、类别数与本提示词四项校验基准的对照；如有差异，按上述校验失败分支处理，不修改数据凑数。遇到必须清洗的情况，说明规则，清洗仅作用于内存副本，并记录前后数量。

### 第二阶段：先看单个商品

列出出现最频繁的 10 个商品类别，展示出现的交易数及其占全部交易的比例。用其中一个商品解释「支持度」，再提出一个问题：热门商品出现在很多规则里，是否就代表规则有价值？暂不预设答案。

### 第三阶段：用 Apriori 挖掘关联规则

在完整数据上进行探索性分析。按购物篮内是否出现某商品编码，不把类别出现次数当成购买数量。

参数固定为：最小支持度 0.01，最小置信度 0.30，最小提升度 1.20；项集最多包含 3 个商品，规则后件只包含 1 个商品。

说明三个指标的含义和分母。报告频繁项集数、置信度筛选后的规则数、提升度筛选后的规则数。按提升度降序排列，同提升度按支持度降序排列，展示前 10 条规则；不足 10 条则如实展示，不暗中降低阈值。

根据实际结果解释每次筛选是否减少了规则数。若置信度筛选后仍有规则，且提升度筛选前后数量相同，说明本次通过置信度筛选的规则也都达到了提升度阈值，并展示这些规则中的最小提升度作为核对；数量相同本身不代表漏做筛选。若置信度筛选后没有规则，则说明没有可供提升度筛选的规则，不计算不存在的最小值。保持原定阈值，不为制造筛选差异调整参数。

规则表至少包含：前件、后件、共同出现的交易数、支持度、置信度、后件支持度、提升度。完整精度的结果保存为 `关联规则.csv`，展示时再四舍五入。

### 第四阶段：解释、复核与判断

从结果中选一条容易解释的规则，回到购物篮原始记录，独立数出总交易数 N、包含前件的交易数 n(A)、包含后件的交易数 n(B)、共同出现的交易数 n(A∩B)。代入公式复核支持度、置信度和提升度，并与规则表比较。

用同一组计数计算反向规则的置信度，说明为什么 A→B 与 B→A 的置信度可以不同，而支持度、提升度相同。

选择最多 3 条规则解释其业务含义。每条都区分「数据中观察到的关联」和「有待验证的经营建议」。说明这份数据没有顾客身份、交易时间、售价和成本，不能据此判断购买先后、因果关系或利润增长。

最后保存可复跑的 `关联分析.py` 和 `分析报告.md`。报告记录数据来源、检查结果、参数、规则摘要、计数复核和局限。明确这是同一份数据上的探索性结果，尚未用独立样本检验，也未验证经营建议的实际效果。展示工作目录与交付文件的绝对路径，以及一条重新运行分析的命令。
