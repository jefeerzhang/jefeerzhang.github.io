0方案概览

本研究的核心问题是：在 agent 能力不断提升的条件下，学生的哪些能力影响他们使用 agent 完成业务任务的最终表现。考察的学生能力包括专业知识与四项通用能力（书面沟通、计算思维、数量素养、AI 素养），本文统称「学生变量」，与 agent 一侧的「能力档」区分。

「agent 越来越强」无法通过追踪真实模型的长期演进来研究，本研究用弱、中、强三档 agent 随机分配来模拟，比较同一项学生能力在不同档位下的预测力：作用保持不变、被 agent 削弱（替代），还是被放大。

设计沿用 Thorgeirsson 等（2026）的 vibe coding 实验平台与相关设计，做了三处关键改动：agent 能力从固定的单一模型改为弱、中、强三档随机分配；被试从有 CS 背景的学生换成经管本科生；因变量从「界面行为是否与样例一致」改为「业务数字算得对不对」和「能否发现 AI 文稿中的错误」。

全文围绕三条主线展开，第一、二条是核心，第三条用于解释：

  1. 哪些能力起作用：控制一般推理后，专业知识、书面沟通、计算思维、数量素养、AI 素养各自能否独立预测产出正确性与验错表现（H1、H2a、H3、H6）。
  2. agent 变强后作用如何变化：每项能力的预测力随能力档升高是保持、减弱还是增强（H2b、H3 的交互估计、H5）。
  3. 能力通过什么起作用：专业知识是否通过定向核验、写作是否通过提示词质量发挥作用；agent 变强是否让人放松核验、从而改变能力发挥作用的空间（中介 M1–M4；H4b–H4d 作为机制证据）。

1研究背景与目的

1.1 背景

Vibe coding 与原文研究。Karpathy 在 2025 年提出 vibe coding 一词，指用户完全通过自然语言指令让 AI 生成可用的软件，自己既不看、也不改生成的代码。Thorgeirsson 等（2026）以 100 名修过 CS 导论、英语达到 C1 的大学生为样本，首次量化了这种「自然语言编程」能力由什么预测：

  • 书面沟通能力与任务表现正相关（Pearson r = .290，p = .003）；控制一般推理（ICAR16）后，偏相关降至 .186（p = .066）。
  • CS 成绩提供独特的预测增量（ΔR² = .125），写作的独特增量较小（ΔR² = .059）。
  • 写作的预测作用约 52% 经由提示词质量中介（间接效应 0.152，95% CI [0.061, 0.279]）。
  • 自我报告的 LLM 使用频率与任务表现负相关（r = −.258，p = .010）。

原文留下的三个缺口。第一，只用了一个模型：全程使用 Claude Sonnet 4（20250514 版），agent 能力没有被操纵，因此无法回答「工具变强以后，人的知识与能力还起多大作用」。第二，样本有偏：被试都有 CS 课程背景，结论不能外推到以业务知识而非编程为主业的人群。第三，因变量只看 GUI 行为是否与样例一致，没有触及业务产出中利害更高的一面——数字算得对不对、因果推得对不对。

为什么选经管本科生。会计、金融、营销等专业的核心工作不是做界面，而是把数算对、把因果判断准，并写成可交付的需求说明和备忘录。AI agent 变强之后，它生成的应用和文书在外观上会迅速趋同，瓶颈转移到两端：一端是把任务说清楚（规格写作），另一端是拦住「看起来像样、实际算错」的输出（核验）。

已有证据的分歧。强工具会替代人的技能，还是放大技能差异？现有证据给出相反的预测。Noy & Zhang（2023, Science）与 Brynjolfsson 等（2025, QJE）发现低技能者获益更大，支持替代；Otis 等（2026, Management Science）在创业者样本中发现高绩效者受益、低绩效者受损，支持互补；Dell'Acqua 等（2026, Organization Science）则用「锯齿状能力边界」概括 agent 在概念判断上的不均衡表现。

两项直接约束本设计的新证据。

  • Cruces 等（2026, NBER w34851）的随机实验（1,174 人）显示，使用 AI 后，不同教育水平组之间的生产率差距从 0.548 SD 缩小到 0.139 SD，约缩小四分之三；但撤掉 AI 后，差距重新出现。这说明替代发生在执行层，技能层面的差距仍在——这是 H1a（专业知识仍能独立预测表现）的理论依据。
  • Caosun & Aral（2026）的动态模型（augmentation trap）表明：当替代足够强时，把认知外包给 AI 会造成永久分化，高技能者兑现潜力，低技能者去技能化；而当 AI 承担教学、反馈或刻意练习的职能时，这一机制会反转。这是扩展实验 E（训练干预）的模型依据。

这一问题在经管教育情境中尚无实验证据。

1.2 目的

本研究把原文的「单模型相关设计」改为「相关设计 + agent 能力三档随机操纵」，并把因变量从 GUI 行为保真改为「业务产出正确性 + 验错」。目的有四，其中目的 1 是核心目的，目的 2、3 用于解释目的 1 的机制，目的 4 是应用落点：

  1. 识别学生变量的作用变化：agent 能力从弱到强变化时，经管类本科生的专业知识与通用能力（书面沟通、计算思维、数量素养、AI 素养）中，哪些仍能独立预测任务表现；哪些被替代（学生变量 × 能力档交互为负）；哪些被放大（交互为正）。
  2. 检验自动化自满：agent 越强、使用体验越流畅，人对错误的接受门槛是否越松；低专业知识者是否受损更大。
  3. 划清 agent 在核验中的作用边界：计算类错误能否交给 agent 代查；概念类错误是否必须由人有针对性地提问才能查出。
  4. 为经管培养方案提供可检验的依据：哪些能力应提高权重（核验、规格写作）；哪些主张还需要额外的训练干预实验才能成立。

1.3 理论框架

  1. 人机互补与锯齿状能力边界（Dell'Acqua 等，2026, Organization Science）。这是一项预注册实验，758 名 BCG 顾问完成 18 项任务：在 AI 能力边界之内，完成量 +12.2%、速度 +25.1%、质量 +40%；在边界之外，正确率反而低 19 个百分点。据此，本研究假定 agent 强在生成与计算执行，弱在业务默认值与概念判断；人的专业知识用来判断对错，而不是把按钮做出来。落到设计上，任务中埋设「默认值陷阱」（agent 在朴素提示下会做错的业务约束），并用 P0 预实验确认三档后端都会踩中。
  2. 生成—核验不对称（沿用原文）。界面好不好、文字顺不顺，人人都能判断；数字与因果对不对，必须懂行才能判断。由此推出：专业知识对验错的预测应强于对生成任务正确性的预测（H1b）。
  3. 自动化自满与依赖校准（Parasuraman & Manzey, 2010；Schemmer 等，2023）。使用高可靠的自动化系统之后，人的接受门槛会放松。在信号检测框架下，这表现为判定标准 c 的移动，而不必然是辨别力 d′ 的下降。这是本研究对「过度信任」的精确化定义。

关于学生变量 × 能力档交互的方向，上述理论与 1.1 的实证证据给出相互竞争的预测：替代（交互项 < 0）、放大（交互项 > 0）或倒 U 形。因此所有交互假设一律双侧检验，每种结果对应的理论解释事先写入预注册。

2研究问题与假设

2.1 研究问题

总问题：在 agent 能力不断提升的条件下，经管类本科生的哪些能力影响其使用 agent 完成业务任务的最终表现？这些能力的作用随 agent 变强是保持、被替代还是被放大？

编号研究问题与原文的关系

RQ4agent 越强：(a) 生成产物是否越完整；(b) 人对 agent 输出的接受门槛是否放松（信任迁移）；(c) 流畅的措辞是否让错误更难被发现？新增
RQ5三条机制路径：写作 → 提示词质量 → 生成（原文机制）；专业知识 → 定向核验 → 验错；能力档（随机）→ 信任 → 漏检新增（机制层）

2.3 识别策略：哪些结论可以做因果解释

能力档是随机分配的处理，其效应可以做因果解释。「能力档 → 信任 → 漏检」路径的前半段（a 段）因果可识别，是本设计最有力的机制证据。

专业知识与通用能力都是观测变量，只能谈预测与机制，不能推出「教了就会」。关于训练效果的因果主张，由扩展实验 E（训练干预随机对照）单独承担。

3实验对象与分组

3.1 对象与纳入 / 排除标准

  • 对象：经管类本科二至四年级学生（会计、金融、经济、工商管理、市场营销、国际商务）。
  • 纳入标准：已修微观经济学或会计学原理中的至少一门；近 6 个月内至少使用过一次生成式 AI。
  • 与原文的差异：不要求「已修 CS 导论」或「用 LLM 写过代码」——这是原文最大的样本偏差来源。原文还要求英语达到 C1，本设计不设此筛选。
  • 排除标准：CS 或软件类辅修超过 12 学分；参加过 P1 或 P2 预实验（题目已暴露）。
  • 招募：不经任课教师之手；若以课程加分作为报酬，必须提供等值的非实验替代作业。

3.3 分组与随机化

  • 设计：被试间因素为 agent 能力三档（L1 弱 / L2 中 / L3 强）；被试内因素为四类任务——T1 复制、T2 扩展、T3 去情境、T4 验错，其中 T4 分为 4A（不能用 agent）与 4B（可用 agent）两个阶段。
  • 随机化时点：场次 2 到场时才随机分档。场次 1 之后的流失发生在随机化之前，不破坏组间可比性；但仍需报告流失者与留存者在场次 1 各量表上的差异。
  • 随机化方法：最小化法（Pocock & Simon, 1975），平衡 DK 三分位、ICAR16 三分位、专业与性别；保留随机成分，以 p = 0.8 的概率分入最能改善平衡的档位。
  • 同场混排：同一场次内三档混合，座位随机；不按场次分档，以免时段、主试、网络状况与档位混淆。
  • 控制需求特征：被试只被告知「使用一个 AI 助手」，不知道存在三档；事后测量感知能力，作为被试侧的操纵检验。
  • 顺序与平衡：T1–T3 的顺序对每名被试单独随机；T4 固定在生成任务之后，4A 固定在 4B 之前；每个任务有两个同构平行版本，随机分配；两份备忘录在 4A、4B 间的分配按拉丁方跨被试平衡。

5实验流程

5.1 总体结构：两场次，间隔 3–10 天

拆成两场有两个理由。其一是时长：两场各环节合计约 200–220 分钟，合并为一场，疲劳会集中在后段任务上。

其二更关键，是处理后测量问题。如果被试先做任务、再测 DK、Writing、MAILS，这些预测变量就会被所在档位带来的挫败或顺畅体验污染。因此，全部个体差异测量放在场次 1（随机化之前），场次 2 才随机分档。

间隔定为 3–10 天，是因为 DK 测验与任务涉及的概念高度重叠，同场进行会启动相关概念。原文中测验与任务的先后顺序对表现没有影响（先测验 .446、先任务 .448，p = .953），但本研究 DK 测验与任务的概念重叠度远高于原文的作文，这一结论不能套用。

操纵净化原则

  • 三档同一模型家族：跨厂商会把能力、输出风格、中文能力、指令遵循习惯一起换掉。
  • 锁定版本，防止版本漂移。原文专门列出了这一风险；本方案早期版本曾举例的 GPT-4o-mini 已被弃用。
  • 控制随机性：能设置 temperature 的设为 0 并固定 seed；记录完整的请求、响应与模型标识；P0 中重复运行，估计残余方差。
  • 剥离速度：agent 生成期间暂停倒计时，并记录延迟。原文选用 Sonnet 4 的理由之一就是快；在限时任务中，速度会与能力混淆。
  • 统一系统提示：三档使用同一系统提示，不压制强模型主动核对的行为——这本身就是能力的一部分。
  • 部署与数据：优先选择中文能力强、开放权重、可在校内部署的模型家族；L3 若使用 API，须签订不留存、不用于训练的协议。

5.5 任务材料

总原则

  • 刺激材料均为可操作的样例应用或可下载的 CSV。禁止把文字说明写成可直接复制的完整需求，否则测到的是复制粘贴。
  • 每个任务有 2 个同构平行版本。
  • 保留原文的功能横幅：样例功能未全部点开时给出提示并记录（原文 300 次提交中仅 3 次未点完）。
  • 泄题防范：被试签保密承诺；同时监测三项泄题信号——首条提示中提前出现样例参数、完成时间异常短、事后自报与他人讨论过。被标记者保留在数据中，另做剔除后的敏感性分析。

T1 复制（高情境）｜定价与促销模拟器

  • 样例可操作的内容：单价、档位折扣、增值税、贡献毛利、盈亏平衡销量。
  • 评分 8 项：档位阈值、折扣计算、增值税、毛利、盈亏平衡、输入校验、结果随输入更新、边界（销量为 0）。
  • 默认值陷阱（经 P0 验证）：
    • 折扣按超出阈值的部分累进计算，而不是达到阈值后全额打折；
    • 输入的单价为含税价，计算毛利前须剔除增值税；
    • 盈亏平衡用单位贡献毛利（不含税价 − 变动成本）计算，固定成本不摊入单位成本。
  • 学生发现这些陷阱需要两个成分：用同一组输入对比样例与自己的应用（VER 成分），以及理解数字为何不同（DK 成分）。因此 TRAP 不是 DK 的纯净近端指标——低 DK 但逐格对数字的人能过一部分，高 DK 但不对样例的人会栽。TRAP 预注册为探索性分析 TRAP ~ DK × VER：预期 DK 的斜率在「对比过样例数字」的子群中更大，与 M2 机制（DK → 定向核验 → 验错）同构，不进确认性家族。P0 另设无样例对照提示验证陷阱的通过路径（见 7.3）。
  • 测试用例 12 组，包括恰好等于阈值、销量为 0、负数或非数字输入。

T2 功能扩展｜社团预算看板

  • 已有功能：收入 / 支出记录与分类合计。
  • 需新增：分类预算预警、剩余预算百分比、「赞助延迟一周到账」的 what-if 分析。
  • 评分 6 项，每项 0–3 分。
  • 候选陷阱：剩余预算百分比的分母是预算额，而不是已支出额；赞助延迟只改变现金到账时点，不改变全年收入合计，期间若现金余额为负，须显示资金缺口。

T3 去情境｜不透明标签计算器

  • 行为一看就懂（例如点 A 使 K 加 1，点 B 使 K 翻倍并把 A 清零）；标签用字母，不暗示用途；规则无需靠试错归纳。
  • 不埋陷阱，作为 DK 的对照任务。
  • 不采用本方案早期版本中「规则靠试出来」的设定：那样测的是 ICAR16 已经测过的归纳推理。

T4 验错（4A + 4B）

两份备忘录：甲为「校园咖啡馆开设外卖窗口」，乙为「文创店进入线上渠道」。每份约 300 字 + 1 张表，各含 6 处错误（3 处计算类 + 3 处概念类），另有 3 条正确陈述作为干扰项。

备忘录甲备忘录乙
计算类TAM（潜在市场总规模）数量级错一档；同一项成本重复计入；把月度数字当作年度数字引用增长率用错基数；折扣后的毛利率算错；合计行与明细不符

4A 的来源匹配（防止 H4b 被归因错配污染）

  • 做法：4A 指导语为「你的 AI 助手刚才根据同一批数据，另写了一份文字稿备忘录」。备忘录在与 T1–T3 相同的界面中呈现（同样的聊天气泡版式、同样的「助手」名称），三档看到的文本完全相同。
  • 原因：如果来源不匹配，L1 组刚见过残缺的产出，会不相信这份备忘录出自同一个助手，从而用「来源审查」代替「内容审查」。这样一来，H4b 的组间差异会被自满以外的机制放大。
  • 配套措施：(a) P2 中加入归因操纵检查，问「你认为这份备忘录是刚才那个助手写的吗」；若 L1 与 L3 的认同率相差超过 20 个百分点，就重写指导语。(b) 主实验保留同一题作为测量变量，按档报告认同率，并报告「控制归因认同后 H4b 是否仍成立」的敏感性分析。
  • 伦理：这属于轻度欺骗，须经伦理委员会批准，实验结束时当场解说，并允许被试撤回数据。

7数据采集方法

7.1 数据来源

  1. 平台日志（自建 vibe coding 平台，结构同原文）：完整提示序列、每轮请求 / 响应与模型标识、回滚、预览 iframe 事件（测试输入、边界值）、计算器调用、功能横幅触发、墙钟与有效计时、每轮生成延迟。
  2. 测验系统：场次 1 各量表的逐题作答与用时（含注意力检查）。
  3. 评分数据：测试用例执行结果、0–3 行为保真评分、PQ / SPEC / 定向提问编码、改正质量评分、双评记录。
  4. 问卷数据：背景、信任、感知能力、置信度、事后问卷。

7.2 评分流程

  • 测试用例（主指标）：每个任务 10–12 组输入与标准输出（容差 ±0.01），用例表作为预注册附录冻结。以 Playwright 脚本辅助执行，人工兜底（生成应用的 DOM 结构不固定）。20% 复评，一致率 ≥ .95。
  • 行为保真（0–3）：评分员只看最终应用，不看聊天记录；20% 双评，ICC(2,1) ≥ .75。原文仅由一名作者盲评，本研究至少两名评分员。
  • 作文：两名中文写作教师盲评；分差 > 10 分时由第三人评分。预算按 21% 的第三评比例预留。
  • 改正质量：20% 双评，κ ≥ .70。

7.3 预实验（冻结材料前全部完成）

P0｜Agent 基准测试（约 2 周；无被试，可与伦理审批并行）

每个任务准备两套标准提示：专家提示（SPEC 5 项写全）与朴素提示（一句话说明目标）；三档各运行 5 次。通过标准：

  1. 分任务达标：T1、T2、T3 各自的专家提示 Y_comp 都须满足 5.4 表目标（含 L3 − L2 ≥ .10）。只报合并 Y_comp 会掩盖任务差异——L3 多出的代码解释器对单文件 HTML 的边际有限、对 4B 验算帮助大；若某任务 L3 − L2 < .10，H4a 在该任务上就有失败风险，并按 2.2 的规则连带 H4b–H5 降级。补救顺序：先为 L3 增加「运行测试用例并回报数字」类工具（仍不显示代码，构念仍是 agent 栈能力）；仍不达标则把该任务降出 H4a 前置条件并在局限中说明。不得用「4B 计算类检出」充当操纵检验——那是 H4c 的因变量，用因变量验证自变量会形成循环。
  2. 每个默认值陷阱在朴素提示下、三档中均被踩中 ≥ 4/5 次；不达标的陷阱换掉。另跑一轮不含样例参数的朴素提示对照：若 agent 无样例可依也能做对陷阱，说明陷阱太浅（模型先验即可避开），须换；只有靠样例参数才做对，才证明通过陷阱依赖人提供测试输入——这正是 5.5 中 TRAP 依赖 VER 成分的设计依据。
  3. 按档报告「提示敏感度」＝专家提示 Y_corr − 朴素提示 Y_corr。若 L3 的敏感度明显低于 L1，即构成替代假说在机制层的证据。
  4. 4B 情境下：L3 在通用审核提示下，计算类错误检出 ≥ 4/5、概念类 ≤ 1/5；在点名具体概念的定向提示下，概念类检出 ≥ 4/5；L1 在通用提示下，计算类检出 ≤ 2/5。

第 4 条把「锯齿状能力边界」做进了设计本身：agent 能答对概念问题，但前提是人先问对。

P1｜量表校准（约 2 周，N ≈ 120–150）

在课堂纸笔或断网机房中施测 DK、CT、Numeracy、ICAR16 中文版；另收集 20 篇作文，用于校准评分员。按经典测验理论筛题，样本量足够时补做 Rasch 分析。P1 参与者不进入主实验。

P2｜实验室预实验（约 2 周，N ≈ 18，每档 6 人）

完整走一遍两场次流程。通过标准：

  • 作文在 20 分钟内能写满；
  • DK 测验 25 分钟内，≥ 80% 的人能做到最后一题；
  • T1–T3 合并均分在 .35–.60 之间（原文总均分 .45，去情境任务 .34）；
  • 每档满分者与零分者各 < 15%；
  • 4A / 4B 每题通过率在 .20–.85 之间；
  • 4A 归因检查：「你认为这份备忘录是刚才那个助手写的吗」，L1 与 L3 认同率差 > 20 个百分点即重写指导语（见 5.5 来源匹配段）；主实验保留该题作测量变量；
  • 统计各档墙钟上限触发率；完成评分员培训与用例表试跑。

不达标则修改任务，不开主实验。

7.4 排除与缺失规则（预注册）

  • 两道注意力检查题都答错 → 剔除。
  • 技术故障（服务中断 > 2 分钟）→ 重新预约，原记录不计。
  • 未点完样例功能 / 有泄题标记 → 保留，敏感性分析中剔除。
  • 某量表 > 20% 未作答 → 该量表记为缺失；主分析采用 FIML 或多重插补（m = 50），不做列删除。
  • 超时任务按已提交的成品评分，不剔除。

8数据分析方法

通用约定

  • 连续变量先换算到 [0, 1]，进入回归前再 z 分数化（与原文一致）。
  • 能力档采用正交对比编码：线性项 cap_lin（L1 = −1，L2 = 0，L3 = 1），二次项 cap_quad（L1 = 1，L2 = −2，L3 = 1）。描述统计另报以 L2 为参照的哑变量结果。
  • 场次数超过 10 时，加入场次随机截距。

8.1 生成任务（测试用例层模型）

主分析以「被试 × 任务 × 测试用例」为一行，因变量为该用例是否通过（0/1），用二项 GLMM 估计。

# 每行 = 被试 × 任务 × 用例，pass ∈ {0,1}
m_corr <- glmer(pass ~ (DK + Writing + CT) * cap_lin + cap_quad +
                  Numeracy + ICAR + major + task + version +
                  (1 | id) + (1 | task:case),
                family = binomial, data = d_case)

# H1c：DK × 情境（T1、T2 = +0.5；T3 = -0.5）
m_h1c <- glmer(pass ~ DK * ctx + Writing * ctx + CT + Numeracy + ICAR + cap_lin +
                 (1 | id) + (1 | task:case),
               family = binomial, data = d_case)

# H2a（与原文可比）：被试层
m_h2a <- lm(y_gen ~ Writing + ICAR + cap_lin + cap_quad, data = d_person)

用例层模型直接处理 0/1 边界，L3 的天花板不会机械地压平斜率；同时报告被试层 OLS，便于与原文对照。若任一档有 ≥ 15% 的被试 Y_corr = 1，以用例层模型的结论为准。

与原文对照

  • (a) 只用 L2 组（n = 80），报告 Writing、CT 与 Y_gen 的相关 r，以及分层 OLS 的 ΔR²（先进 CT 后进 Writing，再反过来）。本研究的 CT 不是原文的 SCS1，因此称为「概念性对照」，不称「复现」。原文参照值：ΔR²(write|CS) = .059，ΔR²(CS|write) = .125。
  • (b) 三档合并、控制能力档后再报告一次（N = 240）。

8.2 H1b：相依相关比较

library(cocor)
cocor.dep.groups.overlap(r.jk = r_dk_aud, r.jh = r_dk_corr, r.kh = r_aud_corr,
                         n = 240, test = c("williams1959", "steiger1980"))

以 Williams 检验为主。Y_aud（18 项）与 Y_corr（约 36 个用例）的信度不同，信度较低的一方，其相关会被系统性压低，因此另报信度校正版：

$$r^{*} = \frac{r}{\sqrt{\rho_{xx}\,\rho_{yy}}}$$

两个校正相关之差用 bootstrap 求置信区间。控制协变量的版本，在 lavaan 中对两个标准化 DK 系数施加等值约束，做 Wald 检验。

8.3 验错任务（题目层模型与信号检测）

# 4A 错误题；miss = 1 表示把错误标成「接受」
m_h4b <- glmer(miss ~ cap_lin + cap_quad + DK + fluency + err_type +
                 Numeracy + ICAR + (1 | id) + (1 | item),
               family = binomial, data = d4a_err)
# H4b：cap_lin > 0；H4d：fluency > 0

m_h5 <- glmer(miss ~ cap_lin * DK + fluency + Numeracy + ICAR +
                (1 | id) + (1 | item),
              family = binomial, data = subset(d4a_err, err_type == "概念"))
# H5：cap_lin:DK < 0

# 4B 错误题的击中
m_h4c <- glmer(hit ~ cap_lin * err_type + DK * err_type + Numeracy + ICAR +
                 (1 | id) + (1 | item),
               family = binomial, data = d4b_err)
# H4c：cap_lin 对计算类的效应 > 对概念类的效应

信号检测分解（次要分析）：令 $$e_j$$ 在错误题取 +0.5、正确题取 −0.5，拟合 probit 混合模型：

$$P(\text{flag}_{ij}=1) = \Phi\left(-c_i + d'_i\, e_j\right)$$

其中 flag = 1 表示把该项标为「需改」。预测变量的主效应对应判定标准 c 的移动：系数为负，表示被试更少标「需改」、更多接受，即接受门槛放松（c 增大）；预测变量与 e 的交互对应 d′ 的变化。自动化自满理论预测，能力档主要移动 c，而不是降低 d′——这比「漏检率升高」更精确。

8.5 等效检验、多重比较与稳健性

  • 等效检验（TOST；Lakens, 2017）：用于 H3「CT 不预测 Y_aud」与 H6「MAILS 不增量预测 Y_corr」。90% CI 完全落在 SESOI（±0.25）之内才算支持等效。预注册中写明：「小于 0.25 的效应，本研究无法与零区分。」
  • 多重比较：确认性家族 9 个检验做 BH 校正；估计类只报效应量与 95% CI；探索类不校正，但逐条标明。
  • TRAP 的近端分解（探索性，见 5.5）：被试层模型 trap ~ DK * VER + ICAR + cap_lin，VER 取「是否用同一组输入对比过样例数字」（0/1）。预期 DK 的斜率在 VER = 1 子群中更大；只报效应量与 95% CI，不做显著性结论。
  • 稳健性分析：
    • 剔除会计 / 金融专业后重跑；
    • PQ 改用模型打分，并报告其与人工评分的 ICC；
    • 用潜变量 SEM 校正 DK、Writing 的测量误差；
    • 中文分词（jieba / pkuseg，报告版本）后计算提示词的 HD-D、MTLD，作三角验证（原文中这两个指标与任务表现的相关为 .310 / .343）；
    • 剔除触发墙钟上限者；
    • 对照被试层 OLS 与用例层 GLMM 的结论。

11扩展实验（可拆分，均不是主实验的前提）

扩展 B｜无 agent 基线 L0（约增加 60 人）

同样的任务，只提供 Excel 与计算器。产物是 Excel 模型，但用同一套测试用例评分，因此 Y_corr 在 L0–L3 之间可比（Y_comp、Y_gen 不可比）；4A 原样可比；4B 在 L0 条件下相当于第二份不能用 agent 的备忘录。用于回答：「agent 提高的是完整度，还是同时降低了正确性？」

扩展 C｜课程情境任务

取财务、营销、管理三门课的真实作业，限时 48 小时，使用同一平台。在班内按账号对个体随机（班级数太少，无法在班级层面对能力档做推断）。评分加入「能否直接交给经理」的整体项。作为实验室结论的概念性复制。

扩展 D｜专业对照

30 名 CS 本科生在 L2 条件下完成同一套经管任务，描述性地比较「CS 学生生成强、经管学生核验强」这一培养目标主张。

扩展 E｜训练干预随机对照（人才培养结论的因果依据）

  • 设计：全部使用 L3；两臂各约 60 人（ANCOVA 下 d = 0.5，80% 功效）。
  • 干预组：90 分钟「规格 + 核验」训练，包括 SPEC 5 项模板、典型业务错误清单，以及「先写下判定标准与预期数字，再看输出」的认知强制（Buçinca 等，2021）。
  • 主动对照组：90 分钟通用 AI 工具讲解，时长与讲师相同。
  • 流程：前测（平行版 T1 + 4A）→ 训练 → 一周后后测（新的平行版本 + 新情境任务，测远迁移）。
  • 调节分析：DK × 训练（补偿性还是增强性），必须检验。Buçinca 等（2021，N = 199）发现认知强制类干预存在「干预造成的不平等」：认知需求（Need for Cognition）高者获益显著更大，而且降低过度依赖最有效的设计，主观评价最差。如果训练只帮到高 DK 者，就等于在经管培养中复制了 Otis 等（2026）与 Caosun & Aral（2026）所预言的分化：高技能者兑现潜力，低技能者去技能化。
  • 为什么需要 E：只有 E 成立，才能写「规格 + 核验训练能提高……」。已有证据表明，无护栏地使用 AI 会损害学习：Bastani 等（2025, PNAS）对近千名高中生的研究发现，无护栏的 AI 辅导提升了平时成绩，却损害了独立考试成绩，有护栏的版本则没有这种损害。Caosun & Aral（2026）的模型进一步表明，如果 AI 承担的是教学、反馈与刻意练习的职能，而不是替代练习，技能侵蚀机制会反转——「先写判定标准再看输出」正属于这一类。

不做：眼动、脑成像、多国样本——对经管培养问题没有增量。
